# MO-Parse 最终语义输出契约

状态：2026-10-19 确定目标契约，2026-10-20 更新来源与语义表示的职责说明。本文规定 MO-Parse 公开接口最终交给下游信息抽取的内容，不规定候选解析管线直接输出的格式；当前表格语义实现尚未满足全部要求。内部表示去版本化不改变本契约的内容要求，也不代表已完成推理验收或部署。

## 1. 目的与交付边界

最终文档应让下游直接读取主体、属性、数值、限定条件和关系，减少重新解释版式、表格和图形的工作。唯一公开文档结果仍为 `result.md`，媒体类型为 `text/markdown`，正文使用标题、段落与多层列表；任务状态、资产索引和下载接口继续使用既有控制协议。本文不规定新的请求参数或第二份公开文档格式。底层解析和研究侧忠实导出可以保留表格与页面信息，后续转换、清理和组装由 MO-Parse 负责，不作为管线研究准入条件。

全部表格内容必须转换为有来源的语义描述，包括字段表、记录表、比较矩阵、混合结构和跨页表。PDF 中的流程图和组织结构图也必须恢复关系并转换为语义描述，优先使用多层列表。最终正文去掉物理页码、页眉、页脚及分页控制信息，不按物理页割裂连续业务内容。

本契约规定内容与最终表达，不预选解析框架、规则或模型。是否采用新方法须按[研究框架](research-framework.md)准备来源标注、质量和成本证据，不能凭最终格式要求直接增加模型。

## 2. 中间结果与最终结果

| 层次 | 允许的表示与用途 | 进入最终正文的内容 |
| --- | --- | --- |
| 来源解析 | 原 PDF、原图、Markdown、HTML、XML 区域定义、网格、图形元素及 Evidence IR；保留物理页、坐标、跨度、页眉页脚角色及候选 | 经来源与关系恢复后采用的业务内容 |
| 语义关系 | 表格的字段、记录、完整标题路径与限定语；图形的节点、连线、方向、条件与层级；引用与确定性状态 | 有来源支持的内容和关系 |
| 最终转换 | 清理页面家具、组织阅读顺序、按语义范围生成段落与多层列表、检查覆盖和引用 | 同一份符合本文的 `result.md` |

前序模块可以继续输出 Markdown 或 XML 区域解析定义，不要求每一步直接生成最终描述。中间 Markdown 表格、HTML 表格和 XML 不能绕过最后转换步骤直接成为最终正文。内部证据保留原始版式，不要求为去掉最终页码而删除来源定位。

公开正文不包含 GFM 管道表、HTML 表格、XML 区域定义、完整坐标 JSON、物理页标记、页眉页脚调试块或分页控制符。必要来源引用采用简短标识，详细页号、区域、原格和图形定位通过内部证据或按需审计解析，不在普通抽取正文中展开。原图可作为可选溯源资产保留，不能替代表格或流程与组织关系的描述。

## 3. 表格语义表达

所有表格类型使用同一目标：完整表达来源内容及其关系，不以“二维比较有用”为理由在最终正文保留表格。字段型按主体或分组组织属性，记录型逐条组织主体与完整属性，比较矩阵按项目和完整比较维度展开，混合结构先分清字段区、记录区、标题区和说明区，再分别表达。

每个值在表达前关联完整行列标题路径、单位、期间、适用范围、附注及来源单元格。来源没有给出、不适用、识别缺失、程序尚不支持和关系冲突分别记录，不凭指标名、数值或模板补造限定语。标签和值从来源读取，连接词与列表层级由渲染器生成。

零、真实空白、破折号、跨度占位和识别缺失不能相互替换。跨度表达的是共享属性、分组标题或说明范围时，应保留对应关系，不能把占位空格输出成多个真实空值。内部换表头、单位变化与跨页继承分别限定作用域，不能对整张表套用首组标题。

跨页表先保留物理来源，再证明完整标题、跨度、单位和延续范围，建立逻辑关系。重复标题只从最终叙述中去重，来源证据保持；不能靠相似首行、同列数或相邻位置补标题。跨页关系未确认时分别描述已确认部分，明确未解决的范围，不把两个片段合成确定事实。

以下为格式示意，不是本项目已测原件或新实验结果：

```markdown
## 公司基本情况

- 股票
  - 简称：示例公司
  - 代码：000000
- 联系人
  - 董事会秘书
    - 姓名：张某
    - 电话：010-00000000
  - 证券事务代表
    - 姓名：原表留空

## 主要财务指标

- 营业收入
  - 单位：万元
  - 2025 年度：1,234.50
  - 2024 年度：1,100.00
- 总资产
  - 单位：万元
  - 2025 年末：8,000.00
  - 2024 年末：7,500.00
```

示例中的单位和期间只适用于各自项目，不能扩散到其他指标。比较值和来源已给出的增减值可完整抄录，不在转换阶段重新计算。公司消歧、指标归一、控制权判断与事件抽取继续属于下游。

## 4. 流程图语义表达

识别图内全部节点、节点文字、分组、连线端点、箭头方向、边标签、判断条件、分支、汇合和回路。只识别图中文字或按坐标顺序排列文字，不算流程关系恢复。泳道和子流程若限定执行主体或范围，必须保留这种来源关系。

多层列表可以分别组织节点与流转关系；图结构不一定是一棵树。汇合、跨层连接和回路使用节点引用表达，不能因列表排版把并行关系改成先后关系，也不能把未标方向的线补成单向箭头。没有给出条件与条件未识别分别说明。

```markdown
## 示例审批流程

- 节点
  - A：提交申请
  - B：审核材料
  - C：完成办理
  - D：补充材料
- 流转关系
  - A → B
  - B → C
    - 条件：审核通过
  - B → D
    - 条件：材料不完整
  - D → B
    - 含义：补充后重新审核
```

以上连接及条件均为格式示意；真实输出只能使用原图明确支持的内容。无法辨认的节点或连线单列为未解决内容，不能据业务常识补齐路径。

## 5. 组织结构图语义表达

恢复主体、部门或岗位节点，识别节点所属分组、上下级关系、连接方向与连线标签；原图给出的比例、职责和附注随对应关系保留。层级明确时用嵌套列表表示，多重归属、虚线联系和交叉关系另列，并保留原图明确给出的关系类型。

```markdown
## 示例组织结构

- 示例机构
  - 部门甲
    - 岗位甲一
    - 岗位甲二
  - 部门乙
- 其他关系
  - 部门乙 → 岗位甲二
    - 原图标注：业务协作
```

上下位置、框线或连接本身不能自动解释为持股、控制、管理或汇报关系。图例和连线明确给出何种关系，就表达何种关系；类型无法确认时说明“连线类型未确认”，不能归一为确定的控制或隶属事实。源图中的关系描述属于 MO-Parse，扩展业务推断属于下游。

## 6. 页码、页眉与页脚清理

物理页号、重复文档抬头、页边重复导航和页脚属于最终输出清理对象，原始位置、文字与判断依据留在证据层。清理依赖页面角色、重复范围、版面位置和正文上下文，不根据顶部、底部或一段纯数字直接删除。

业务标题、真实章节编号、表内期间、金额、单位、附注、法律声明、签章、签字和日期即使出现在页边也须保留。页脚中的业务说明应移入对应语义范围；重复的文档标题在需要时保留为正文标题，去掉的是逐页重复副本。

清理后的最终文档不出现物理页分隔注释、页眉页脚角色注释或独立排版页码。页码仍可在内部来源定位使用；原文句子中有业务意义的编号或页码引用不能无条件删除。无法可靠区分业务内容与页面家具时记录未解决状态，并保留内部证据，不能以误删业务内容换取形式通过。

## 7. 未完成、失败与覆盖

完整转换是目标要求，不能靠强制改写不确定关系或删除失败区域达成。来源解析、语义关系与最终表达各自记录覆盖；表格和两类图形的原件清点与最终描述逐项对应，漏检区域也属于未覆盖，不能只统计已检出片段。

某一区域未完成时，内部保存原表、原图、候选和原始文本；可供诊断的部分文档用多层列表说明已确认内容、未解决范围及原因，禁止混入原始表格伪装为最终转换成功。程序不支持、文字未识别、关系冲突和原件不可辨分别列明。未解决清单不是完整语义描述，相关任务不能被宣称已满足本契约。

HTTP 200、`/ready`、既有 Job `completed`、文件可下载和表格被删除都不能证明最终转换完成。后续实现必须将语义不完整与既有 `partial` 等任务状态一致关联，具体服务行为以实现和接口验收为准；本文不宣称当前表格语义实现已具备这种联动。来源保全成功与语义完成分别报告，未知不算正确，也不算零成本。

## 8. 最终转换与验收

最终转换在来源解析、关系恢复及必要资产处理之后执行，并对同步响应、异步结果、下载和持久化使用同一份正文。MO-Parse 接入不同后端后，由服务履行同一公开契约；底层后端及研究比较无需调用这段转换或直接输出最终格式。最终接口格式不因前序使用 Markdown、XML 或其他结构而改变。

- 全量清点来源表格、流程图和组织结构图，核对所有内容及关系的最终去向，保留未检测、未识别和未完成的分母。
- 对 MO-Parse 转换功能使用正确结构和关系分别检查关联与渲染，再在真实完整 PDF 的服务结果中核对标题、单位、期间、附注、节点、边、方向、条件和层级；这些测试不是候选解析管线的前置要求或能力成绩。
- 检查最终正文没有 GFM 或 HTML 表格、XML 区域定义、图形仅有 OCR 文字或原图链接、页码、页眉、页脚、分页标记及完整坐标调试块。
- 检查正文阅读顺序、段落连续性、有效标题、签章日期和业务附注完整；清理页面家具不能降低内容保全。
- 分别报告格式符合性、表格与图形的完整正确语义覆盖、来源引用、未解决范围和任务状态；转换费用与解析费用分开，如测完整服务 worker 则另报该口径，不混入管线排名。
- 用完整原件验证响应、持久 Markdown、下载与资产一致；内部来源证据可追溯，诊断与业务正文分离。

## 9. 当前实现差距与迁移

当前表格语义实现仅支持完整对应的矢量网格、部分标题作用域与字段样式，仍输出保全 GFM、物理页标记和页面家具；图片可见文字识别没有覆盖流程或组织关系。`semantic-view`、`semantic-source`、`semantic-summary` 及[表格来源与证据约定](table-source.md)用于当前有限转换和来源审计，不划分内部协议版本，不能据此判定满足本契约。GFM 仅是具体显示格式，服务允许直接读取管线原生结构后转换为目标文档。

解析预期结果与语料的生成已在其他项目开展。后续服务开发核对外部交接的对象清单、独立关系与页面家具标注，验证转换方法并单独测量费用，再扩展关系处理与最终组装；不增加无依据的第二解析器。解析研究独立比较原始内容、结构与解析成本，无需等待服务转换完成；服务失败也不能未经定位归为解析管线错误。处理层、来源许可和实现依赖以[技术路线](technical-route.md)为准；代码、真实完整原件验收和部署尚需另行推进。历史服务结果按生成时的协议保存，不因文档修订被重写；新目标与旧结果分开判断。
