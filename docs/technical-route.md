# MO-Parse 技术路线与职责边界

状态：2026-10-20 明确解析研究、目标结果转换与接口工程的职责，不是部署完成说明。本轮不执行推理或发布。两项研究目标及解析方法的研究顺序见[研究框架](research-framework.md)，服务对外要求见[最终语义输出契约](output-contract.md)。

## 1. 两项工作的交接点

两项研究目标分别是解析管线研究和解析结果到目标结果的转换研究。前者从完整 PDF 到该管线的解析结果，比较来源内容、结构和实际解析成本；后者从实际解析结果到符合最终契约的 `result.md`，研究内容保全、表格与图形关系表达、页面清理及其质量与成本。MO-Parse 工程负责后端接入、转换方法的实现、文档组装和接口交付。交接点是已有解析结果，不是要求候选管线直接生成符合服务最终契约的文本。

表格来源、语义关系和本链路审计只维护当前定义，随代码直接修改，不维护内部协议版本。处理流程为管线原始结果 → MO-Parse 结果转换 → 目标文档；GFM 只属于具体显示方式，服务可直接使用已有结构，不要求先转换成 GFM。来源使用见[表格来源与证据约定](table-source.md)，显示映射见[架构说明](architecture.md#表格显示映射)。

例如，管线输出含表格和页码的 Markdown，或者 HTML 表格、XML 区域、JSON 结构，都可以是正常解析结果。研究要核对这些结果是否忠于原件。MO-Parse 再将其中的表格转换成多层语义列表并清理页面信息；转换失败首先检查服务代码，不能直接算作上游解析方法的错误。

| 范围 | 要交付什么 | 质量与计时边界 |
| --- | --- | --- |
| 解析研究 | 八个固定配置的原始解析、忠实 Markdown 导出、必要资产及记录 | 原件内容和结构是否恢复，完整解析 worker 花费多少 |
| 目标结果转换研究与实现 | 读取选定后端已有结果，转换为符合最终契约的 `result.md` | 已有信息是否丢失、关系是否正确、内容是否误删、未完成范围及转换成本 |
| 后端接入与公开接口工程 | 适配后端，同步、任务结果、落盘与下载使用同一 `result.md` | 保真读取、格式、状态、资产和结果一致性；按工程契约验收，不单列研究目标 |

后端字段适配和公开 API 交付属于工程实现。转换研究集中于如何忠实生成目标内容与关系，不能将协议兼容、文件可下载或 HTTP 成功作为方法研究结论；接口耗时也不能代替解析或转换的直接计时。

服务可以按需要查原件恢复解析结果未提供的信息，但这属于 MO-Parse 转换能力及其费用，不能回填为某候选管线本身的解析成绩。新增方法仍须有适用类别、质量与成本证据；不默认在 MinerU 后调用独立 Docling 复核。

## 2. 解析管线研究路线

研究按[八步顺序](research-framework.md#2-管线研究的顺序)推进：明确解析问题与范围，建立原件类别和低成本观测，固定八组对照条件，执行完整 PDF，分析分类别质量与成本，再决定固定方法或是否研究路由，开展路线内调优，最后给出适用边界和接入建议。

本轮八组定义只在[管线计划](../benchmark/pipelines-to-test.md)维护。各组保留本身提供的 Markdown、HTML、XML、JSON、SDK 对象与图像；研究侧 Markdown 只是忠实导出，允许表格和页面信息。共同处理限于声明的前处理、结果整理、忠实导出和必要资产，不包含服务的语义转换及最终正文清理。

解析预期结果与语料的生成已在其他项目开展，本项目接收完整原件与独立标注的冻结版本，不重复生成语料或金标。交接范围、配置身份、输入权限、原始结果保存、评分读取及直接处理计时就绪后，按授权执行声明的对照。无需先开发统一语义数据模型、完成全部表格/图形转换或通过服务最终格式检查。不能为了比较而在读回代码中补标题、改数字、增加连线或用原件答案修正某组。

固定完整配置中已声明的原生/视觉分工属于该配置；未来按类别选择方法的路由则由真实质量差异和净收益决定。原生和纯视觉输入权限按配置维持，不能将服务后来使用的原生字层或另一解析器答案倒灌给纯视觉组。

## 3. MO-Parse 服务处理路线

![MO-Parse 服务：接收任务、调用解析、读取结果、转换内容、组装正文、接口验收与返回保存](assets/workspace-pdf-pipeline.svg)

图中的解析后端只负责自己的解析输出，后面的转换、清理和最终格式属于 MO-Parse。解析研究计时止于解析结果及其忠实导出就绪；图中的服务全过程不能直接当作八组解析耗时。

本路线中第 3 步读取实际解析输入，第 4、5 步实现目标结果转换，第 1、2、6、7 步承担任务、后端调用及接口工程。转换研究按[相应问题与证据](research-framework.md#32-目标结果转换研究问题)比较内容与关系的恢复和表达方法；字段适配、协议返回及其功能测试按工程要求完成，不另设研究课题。

| 步骤 | MO-Parse 的工作 | 产物与检查 |
| --- | --- | --- |
| 1. 接收原文件与任务 | 保留原件身份、范围、请求所有权及任务选项 | 输入与任务稳定关联 |
| 2. 调用选定解析后端 | 按声明方式获得文字、布局、表格或图形结果及原始资产 | 原始响应可核对，允许保留原表和页面信息 |
| 3. 读取已有解析结果 | 用接入代码读取本后端已有的文字、结构、媒体和来源，保留缺失与失败 | 不因转译丢信息，也不在字段读取中补造事实 |
| 4. 转换内容并清理 | 由 MO-Parse 绑定表格限定关系，恢复并表达流程与组织关系，区分页面家具和业务内容 | 来源支持的描述与多层列表；未解决范围明确，业务内容不误删 |
| 5. 组装文档正文 | 核对跨页范围、顺序、标题单位附注和图关系，生成同一份语义 Markdown | 全部内容有去向，无原表、物理页码、页眉页脚和调试信息 |
| 6. 验收接口结果 | 分开检查格式、内容覆盖、语义正确性、资产引用与完成状态 | 未完成转换不能用任务执行成功冒充完整合格 |
| 7. 返回并保存同一结果 | 同步响应、异步结果、落盘、下载及资产引用使用同一版本 | 正文 SHA 与引用一致，旧结果不被静默改写 |

表格标签和值从源格读取，完整行列标题、单位、期间和附注先正确关联再表达。流程图保留节点、方向、条件、分支与回路；组织图保留层级和明确的交叉联系，多层列表不能把一般图强行变成树。不能通过删掉未转换对象取得格式通过。

内部保留原件、物理页和位置以便追溯；去掉最终正文中的物理页码不意味着删除内部出处。图像或 OCR 文字可以是解析管线的原始产物，但单有它们不等于服务已完成图形语义描述。

## 4. 结果读取与错误定位

读取代码按后端实际返回的字段工作，检查原文、结构、来源和资产是否被保真传递。MO-Parse 转换使用自己的内部表示；候选无需实现这个表示。结果读取、功能测试和错误定位属于工程工作，不作为候选解析方法的统一语义接口要求。

| 看到的问题 | 检查哪里 | 结论的范围 |
| --- | --- | --- |
| 原始结果已漏字、错格或丢图 | 原件与本方法原始响应 | 该解析方法在此材料上的实际缺陷 |
| 原始结果有内容，读回或导出时丢失 | 原始响应与读取/导出记录 | 研究或服务接入代码缺陷，先修读回 |
| 表格字值正确，服务列表绑定错单位 | 解析原文与 MO-Parse 转换 | 服务关联错误，不能按列表错误给解析器扣分 |
| 正确描述在下载中被旧表覆盖 | 转换结果、组装、持久文件与下载 | 服务组装或接口一致性缺陷 |

以正确表格结构测试 MO-Parse 转换函数，只能证明该函数对这些输入的行为；以真实解析结果测试服务，才能观察实际接入问题。两者都不能代替解析管线与原件的质量对照，也不是管线比较的前置门槛。

## 5. 实现与评价顺序

| 工作 | 依赖与交付 | 完成条件 |
| --- | --- | --- |
| A. 准备解析研究 | 外部原件与独立标注交接、八组身份与资源、忠实读取导出、评分和计时 | 原始结果可比较，允许失败、未知和能力不同 |
| B. 执行解析研究 | 固定条件下完整原件的内容、结构、覆盖、失败及费用 | 给出证据支持的适用边界，必要时再研究路由和调优 |
| C. 研究并实现目标结果转换 | 实际解析结果、独立内容与关系标注；比较转换方法并实现接入、清理与文档组装 | 明确适用范围、语义质量、完整覆盖和成本；转换功能分别测试，并用实际解析结果检查内容和未知状态 |
| D. 验收与发布服务 | 已实现功能的完整 PDF、响应/落盘/下载、资产、状态和资源 | 最终契约与实际运行通过后，按授权发布 |

A、B 对应解析管线研究，C 对应目标结果转换研究及其工程实现，D 是接口与服务的工程验收和发布。C 可在解析研究进行时使用现有后端推进，不要求等待所有解析比较完成，也不能反过来阻塞 A、B。B 的方法结论可用于后续后端选择；D 的验收不作为两项研究的方法比较结果。实验和部署仍分别遵循当前授权，本轮文档修订不启动它们。

解析处理时间从 worker 开始处理完整 PDF 到原始结果、研究侧忠实 Markdown 和必要资产就绪，包含必要渲染及全部声明解析工作。MO-Parse 转换另记费用；如测完整服务 worker，再直接测量这一独立口径，不能把重叠阶段求和或混进解析排名。HTTP、排队、轮询、下载及纯持久化不计解析处理时间，初始化和预热单列。

## 6. 现有实现的复用与缺口

| 现有部分 | 可复用的能力 | 服务侧仍需补齐的工作 |
| --- | --- | --- |
| [解析服务](../app/services/parser_service.py)及后端适配 | 请求所有权、共享 deadline、原始来源与资产 | 划清原始结果和服务转换的调用边界，避免旧后处理覆盖正文 |
| [表格来源服务](../app/services/table_service.py) | 来源格、跨度、片段和严格跨页证据 | 保全内容并交给服务转换，未知首行不冒充表头 |
| [PDF 矢量证据](../app/services/pdf_table_evidence_service.py) | 适用原生表的格线、字形及出处 | 只作为适用的来源方法，不要求所有候选解析器提供矢量网格 |
| [表格关系模型](../app/models/table_semantics.py)与[当前转换服务](../app/services/table_semantics_service.py) | 来源引用、部分作用域、原文读取与有限列表转换 | 无格线、扫描、混合区、完整限定语与未转换内容处理 |
| 当前图片识字 | 原图、可见文字与资产身份 | MO-Parse 的流程/组织关系恢复和表达，不能用图像链接替代完成 |
| 现有文档组装 | Markdown、资产及任务持久结果 | 家具清理、完整语义正文、状态与返回文件一致性 |

当前表格语义实现仍保留部分表格和页面信息，也未完成两类图形关系；这说明服务功能尚不完整，不能据此推出某解析框架更好或更差。八组解析比较仍待按统一协议准备和执行，历史有界转换结果不改写为新研究成绩。

### 6.1 现有调用与计时字段

以下结论来自 2026-10-19 的源码检查，不是新运行或部署证据。现有服务调用链尚未按本轮研究口径拆出正式比较入口；不能把目标图上的交接位置当作代码中已经存在一个可直接调用的完整研究函数。

| 位置 | 当前实际工作 | 与解析研究的关系 |
| --- | --- | --- |
| [ParserService.parse](../app/services/parser_service.py) | 调用原生/SDK 分支后，执行 PDF 表格证据补充、来源日志、导出、IR、资产及表格语义转换 | 这是服务处理入口，不能整个用于八组原始解析对照；关掉语义开关也未排除其余服务处理 |
| 同文件的 `_parse_native_pages` 与 `_apply_scan_ocr` | 来源观测后调用所选原生后端及 GLM SDK | 可复用声明的分类和分支逻辑，但单个分支返回不是完整混合配置的结束 |
| [DoclingStandardParser.parse](../app/parsers/docling_standard.py) | 原生页转换及其结构导出，返回页面、表格和图片候选 | 是 P01 的现有接入起点；P02 的模型选择与完整公共前处理仍待准备 |
| [MinerUNativeRemoteParser.parse](../app/parsers/mineru_native_remote.py) | HTTP 提交与轮询、原始证据写入，再读回和渲染原生结果 | 可参考原始响应读法；其客户端耗时包含传输和日志，不是完整解析耗时 |
| [native worker 的 `_parse`](../native_worker/server.py) | 先读页数尺寸，再调用 MinerU `parse_async` 并导出 source blocks；tier 写为 advanced | 是 P07 原生分支的实现起点，未覆盖共同前处理、GLM 分支和完整研究侧导出；P06 需显式 Standard |
| [PDF 表格来源服务](../app/services/pdf_table_evidence_service.py)及[表格语义转换](../app/services/table_semantics_service.py) | 服务在后端返回后从原件补充来源，再进行有限关系转换 | 归 MO-Parse 服务能力，不能在原始结果比较中免费修复标题或关系 |

| 现有字段 | 源码中的区间 | 正式研究处理方式 |
| --- | --- | --- |
| 服务 `usage.duration_ms`、IR `runtime.duration_ms` | 从进入服务处理前开始，包含内部等待、可能的初始化、来源日志及语义转换，最终阶段又更新 | 保留原字段含义，不能当八组解析计时或由减去语义时长得到 |
| MinerU 远程适配器的 `usage.duration_ms` | 含 HTTP 提交、轮询、响应及来源写入，记录点又早于后续逐页读回 | 仅为当前客户端区间，不作为正式成本指标 |
| native worker 响应 `duration_ms` | 从 MinerU 调用前到 source-block 导出后；前置页数与尺寸读取不在该区间 | 只能作局部诊断，不能冒充完整 PDF 或混合管线耗时 |
| `_semantic_duration_ms` | 现有表格语义转换 的 `apply` 调用区间 | 仅是服务转换的局部费用，不代表完整语义服务或全部后处理 |

后续研究入口应在隔离的执行配置内直接覆盖声明的完整解析工作并保存原始结果，另行核对忠实导出和资产范围。现有字段和生产接口不因本文而改变；本轮不编写新基准工具、不启动推理或重启服务。原始解析就绪后，MO-Parse 仍可在服务路径继续转换和返回最终正文。
