## 实际错误路径及修复

原始 Docling `table_cells` 和 `document.texts` 均无该标签，表格模型完全遗漏了
覆盖 `(row=1..8, column=0)` 的单元格。
`table_service._anchored_rows` 只导出已有 `cell.text`，这段文字在进入导出前已经缺失。
合法空白格也可能没有显式单元格，因此覆盖缺口不会自动使整个表格失效。
原生阅读顺序修复排除表格区域，并不补全文字。

新增 `native_table_service.restore_missing_native_merged_cells`，在 Docling 页面导出前执行：

1. 仅检查有覆盖缺口、结构有效的 Docling PDF 表格。
2. 从原件绘制线条识别矢量网格，唯一匹配表格范围、行列数及完整网格边界。
3. 逐一核对已识别单元格的文本及 rowspan/colspan，仅忽略排版空白，保留负号和标点。
4. 只恢复原件网格证明、且范围完全未被占用的非空合并单元格。
5. 完整矩形提取必须与唯一归属的原生文字一致；空格、冲突、歧义及无可靠网格保持原样。
6. 同步补建 `TableCellFragment`、锚点 `rows`、原生来源证据及 GFM，保留来源页和完整跨度。

本例补建 `row_span=8` 的原件单元格，证据为
`{docling:null, native:"历次筹资情况", final:"历次筹资情况"}`。
不依赖财务指标、业务词典或推测期间。PyMuPDF 表格查找通过锁串行处理其共享提取状态。
仅在确实补全时记录 `native_merged_cell_restored` 信息诊断。
