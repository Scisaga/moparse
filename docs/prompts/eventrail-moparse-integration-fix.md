# Eventrail 接入 MO-Parse 提示词

请在 Eventrail 仓库修复 MO-Parse provider 的接入流程，完成代码、测试和真实 Adapter 验收。服务接口以实际 OpenAPI 为准，最终内容目标见[语义输出契约](../output-contract.md)，当前有限转换和来源审计见[API](../api.md#表格关系与来源引用)及[表格来源与证据约定](../table-source.md)。实际构建与历史记录见[运行配方](../runtime-recipes.md)。本提示词定义后续接入要求，本次整理不修改 Eventrail 或启动新解析。

## 必须实现

1. 对已配置的 provider，`/health.service` 精确接受 `mosaicparse` 和 `moparse`，继续校验认证、响应结构、容量和 `/ready`；未知名称不能放行。服务软件版本、实际构建与任务终态分别保存。
2. 使用异步任务接口，收到 202 后立即持久保存业务尝试 ID、provider job ID、输入 SHA256、实际页数、选项与时间。网络恢复、进程重启和轮询重试只 GET 已有任务；同一业务尝试用唯一约束避免并发重复提交。
3. 服务没有已验证的公开 POST 幂等键。POST 可能送达但响应丢失时记录 `submission_unknown`，不自动重 POST；`X-Request-ID` 仅作追踪。明确 `429/queue_full` 可有界退避；已获 job ID 后不再次提交。
4. 分别配置连接读写超时、上传预算、队列预算、服务端执行预算、结果读取预算和业务总 deadline。单次 GET 超时不代表服务端 `parse_timeout`；本地等待到期保留远端任务，显示待确认并支持续取。
5. 按持久 job 的 `status/error` 处理 `completed`、`partial`、`failed`、`cancelled`。`partial` 保留真实结果与原因；不得用旧正文替换失败结果，不能从 HTTP 200 或已完成页数推定全文正确。
6. 仅在用户取消或已有授权取消策略触发时操作本业务任务。`DELETE` 对活跃任务表示取消，对终态任务表示删除，不能无条件重复 DELETE。取消先显示请求取消并继续查询，直到实际终态；本地停止等待不代表 GPU 已停止。
7. `/retry` 创建后继任务，不是原任务续取；新尝试必须记录原因、上限及旧新关联。GET/SSE 断流可有界恢复，持久 job GET 是恢复依据；相对结果地址按 provider origin 解析，认证信息不能转发任意外域。
8. 原始 Markdown 与 SHA256 单独保存，显示或评分派生件另存。表格来源和语义表示只使用当前定义，不为旧结果增加版本解码或迁移；历史证据原样保存。需要诊断 GFM 显示时，只有显式声明且实际全空的 synthetic header 可从来源投影剥离，规则见[表格显示映射](../architecture.md#表格显示映射)。显示行映射不能应用到语义列表，不在接入端补表头、跨页合表或猜期间。
9. 目标结果中全部表格、PDF 流程图和组织结构图应为有来源的语义描述，优先多层列表，去掉物理页码、页眉页脚及分页调试信息。流程分支与回路、组织层级与交叉关系均需保全，只有图中文字或资产链接不算完成。当前混合输出可原样保存为诊断证据，并明确记录契约未完成，不能把 `semantic-summary` 或 Job 完成当作全部语义覆盖。
10. 确认服务端实际实现和验收覆盖后再认定满足最终契约；旧 `semantic-view`、`semantic-source`、`semantic-summary` 不包含完整图形及页面清理状态，不能从它们推定缺失能力已实现。未支持、识别缺失、来源歧义与冲突分别呈现，不在接入端删除残留表格或自行生成关系来伪装完整结果。

## 请求预算

显式 `timeout_seconds` 的范围为 `1..86400`；省略时采用服务端实际配置。服务端默认值以实际配置为准，各服务端阶段共享剩余执行deadline，取消和超时清理可能延后终态返回。请求开始前保存实际配置和构建身份，排队窗口与执行窗口分开。

应按真实页数与路由估算预算，优先使用同字节文档在相同配置下的实测；native、SDK与语义关联渲染费用分别记录，保留启动及网络余量。MinerU 后不再运行独立 Docling 核验。没有足够测量时不承诺通用p95/SLA；未标定输入使用业务允许的有界默认，并保留远端任务续取能力，不能因本地超时叠加新推理。

## 验收与交付

测试覆盖服务标识、ready=false、认证与容量错误、202 持久化、进程重启续取、POST 响应丢失、partial、客户端等待到期、取消完成竞态与禁止重复提交，并检查调用次数。目标内容检查覆盖多层列表、表格完整限定语、流程方向与条件回路、组织层级及交叉关系、无原表和页面家具，以及业务附注与签章日期保全；来源保全、接口行为与最终契约通过分别记录。通过真实 Adapter 处理完整原件，保存输入 SHA、页数、实际选项、唯一 provider job、服务构建、状态、时间及原始结果 SHA；每份新尝试仅提交一次。

接入端负责可靠任务管理、预算和状态呈现。解析服务负责正文、表格及两类图形的语义转换、最终页面清理、来源保全、真实取消和执行进度；发现内容缺陷保存原始证据交给服务端处理，不在接入端改值、补表头或隐藏未知状态。
