# MO-Parse 输出规范

状态：2026-10-21 明确图片语义化不在当前范围，区分数据表与网格排版，补齐 Markdown 与图片的输出包约定，并将可选来源映射统一放入 `manifest.json`。本文规定目标交付，不代表代码或部署已满足全部要求；当前实现差距见第 9 节。候选解析管线的原始输出不受此最终格式约束；先确认各管线原生输出，再设计适配与共同组装，逐组格式和逻辑见[输出与适配说明](../pipelines/README.md)。

本文是人可读的输出规范（spec），覆盖文件组织、内容处理、来源信息与验收，不是机器可校验的 JSON Schema。

## 1. 目的与交付边界

交付内容由 `result.md` 和关联图片资产组成，并提供将两者一起下载的 ZIP 输出包。`result.md` 是唯一文档正文，媒体类型为 `text/markdown`，使用标题、段落、多层列表和图片引用；“唯一正文”不表示只返回文字或省略图片。任务状态、资产索引和下载接口沿用既有控制协议，不增加第二份公开文档格式或新请求参数。

已确认具有字段、记录或行列数据关系的表格转换为有来源的语义描述，包括比较矩阵、混合结构中的数据表区域和跨页表。网格、边框、对齐或后端的 `table` 标签不等于语义表格，具体区分见第 3 节。最终文字正文清理物理页码、页眉、页脚及分页控制信息，不按物理页割裂连续业务内容。

图片语义化明确不做：当前范围不包含流程图、组织结构图、统计图表或照片的语义解释，不恢复节点、连线、方向、条件、层级、趋势或场景，也不将其列为待实现功能或验收门槛。图片按来源保全、引用和交付；已有可选 OCR 仅提取可见文字。

本契约不预选解析框架、规则或模型。底层解析和研究侧忠实导出可以保留表格、源图与页面信息；后续转换、清理和组装由 MO-Parse 负责，不作为管线研究准入条件。方法采用依据见[研究框架](../research/research-framework.md)。

### 1.1 PDF 内嵌图片

保留业务内容中的插图、流程图、组织结构图、统计图表、照片、印章和签名图像，在正文对应位置使用图片引用，并保留来源已有的图题、caption 和业务说明。替代文字使用来源图题或中性名称，不生成图意。纯装饰、重复页眉标识等内容依据第 6 节清理，不能按尺寸、位置或重复出现直接丢弃业务图片。

能独立提取的位图保存为图片文件；由矢量绘制、多个图像对象或遮罩共同组成的图形，允许按完整来源区域渲染为图片，不能只导出零散对象而丢失可读内容。内部记录物理页、区域、出处及提取或渲染方式。页面图片、区域裁图与嵌入图像的原始字节分别标明，不能把渲染裁图称为原始嵌入文件；整页来源图也不能冒充已逐项提取全部插图。

图片保全独立于 `describe_images`。关闭识字仍须提供图片及引用；开启后可附上可见文字，不能将 OCR 阅读顺序解释为流程或组织关系。源图交付是图片内容的有效输出，不因未做语义化而判为不完整。图片缺失、损坏、裁切不全、引用错位或已请求的 OCR 失败分别报告。

### 1.2 Markdown 与图片的输出包

沿用 `GET /v1/content/jobs/{id}/bundle` 作为打包下载入口，目标 ZIP 至少包含以下内容；这是待落实的交付要求，当前实现见第 9 节：

```text
result.md
manifest.json
assets/image-0001.png
assets/image-0002.png
```

上述图片路径为示例，包内文件使用唯一相对路径即可，不要求每张图片增加一层 `asset_id` 目录或另建编号体系。现有在线资产接口继续使用既有 `asset_id`，包内可保留它作为关联信息。`result.md` 引用的图片必须进入包内，解压后无需连接服务即可读取正文和查看图片。

`manifest.json` 统一保存文件清单、校验信息及已提供的来源映射，不另建 `source-map.json`。它不是第二份解析正文；完整坐标、内部审计日志和原始 SDK 响应不混入普通交付。目标内容按以下范围组织，不将现有清单字段视为已经实现这些要求：

| 信息 | 内容 |
| --- | --- |
| `source` | 原 PDF 文件名、SHA256 和总物理页数；原 PDF 本身不因此自动加入输出包 |
| `markdown` | 包内 Markdown 的相对路径与实际文件 SHA256 |
| `assets` | 各资产的唯一包内路径、SHA256 和文件类型；可附尺寸、字节数、既有 `asset_id` 及来源页 |
| `source_map` | 可选的正文来源映射，按下述规则关联最终 Markdown 范围与原 PDF 物理页 |
| `warnings` | 已知缺失、失败或跳过项，区分完整交付与部分结果 |

有来源映射时直接写入 `source_map`，无需拆分文件。PDF 物理页与 Markdown 物理行均从 1 起算，行范围包含起止行，不使用阅读器显示页码或渲染后的自动折行。每项允许一个 Markdown 行范围关联多个来源页；同一来源页也可对应多个不连续范围，以覆盖跨页段落、表格展开和阅读顺序调整。图片文件身份与出现位置分别记录，重复使用同一图片不表示只有一处来源。

映射须绑定 `markdown` 中包内最终文件的 SHA256，在最终正文与图片路径确定后生成或核对，不能复用改写前的行号。只填写已确认的范围，明确完整、部分或未生成的覆盖状态；没有生成映射不能以空列表冒充完整覆盖。当前不将全文行号映射设为基本打包的前置条件，也不因未提供该可选字段判定输出包失败。

同步响应、异步结果、单独 Markdown 下载和持久化正文保持相同 UTF-8 字节。为支持离线图片，打包时只允许把同一正文中的在线资产地址映射为包内相对路径，不得重新解析、改写文字、改变顺序或替换图片内容；按地址映射核对正文一致性，包内 Markdown 的 SHA 可以因此不同。资产文件保持各自校验值，无图文档仍包含 `result.md` 与清单。现有鉴权继续适用于在线结果、资产与 bundle。

## 2. 中间结果与最终结果

| 层次 | 允许的表示与用途 | 进入最终正文的内容 |
| --- | --- | --- |
| 管线原生输出 | 所用完整配置实际提供的 SDK 对象、JSON、Markdown、媒体与状态；保留分支、来源和实际字段 | 经本组适配后采用的已有内容；不预设所有后端同形 |
| MO-Parse 管线适配 | 按本组说明读取文字、结构、页序、坐标、角色和媒体，保留原生信息及缺失 | 带来源的正文、表格候选、图片及未解决范围 |
| 内容分类与表格关系 | 区分数据表、网格排版与未知区域；建立数据表字段、记录、完整标题路径及限定语 | 来源支持的表格关系；布局区域的正文 |
| 最终转换与交付 | 清理页面家具、组织阅读顺序、生成段落与多层列表、关联图片及核对覆盖 | `result.md`、图片文件及对应输出包 |

每条管线的最终原生产物和读取逻辑先在[逐组说明](../pipelines/README.md#管线索引)确认，再设计服务内部表示和最终组装。前序模块允许 Markdown 或 XML 等表示，不表示本轮每组实际都有这些格式，也不要求每一步直接生成最终描述。中间 Markdown 表格、HTML 表格和 XML 不能绕过最后转换步骤直接成为最终正文。内部证据保留原始版式，不要求为去掉最终页码而删除来源定位。

公开正文不包含 GFM 管道表、HTML 表格、XML 区域定义、完整坐标 JSON、物理页标记、页眉页脚调试块或分页控制符。必要来源引用采用简短标识，详细页号、区域和原格定位留在证据层。图片引用是正文允许的内容，关联图片属于交付组成部分。已确认为数据表的区域仍须完成表格转换，不能仅以截图和链接冒充已完成。

## 3. 表格语义表达

### 3.1 先区分内容关系与网格排版

PDF 可能用网格摆放段落、标题、栏目、独立文本块和插图，解析器也可能将这些区域标为 `table`。格线、矩形单元格、列数、对齐、字形匹配或解析器标签都不能单独证明字段和值、记录或比较维度的关系；来源网格可用与语义表格成立分别判断。

- 数据表：来源明确支持字段与值、逐条记录或行列数据的关联，再建立语义关系并转换。
- 网格排版：网格用于放置正文或图片，按来源支持的阅读顺序恢复标题、段落、列表与图片引用，不凭所在单元格制造“字段：值”或行列层级。
- 用途未确认：保留可确认的内容与内部完整来源，明确未确认的类别、顺序或关系，不默认当作数据表，也不为了取消表格格式而拼接成确定叙述。

同一网格可同时包含正文、数据表和图片，应按有证据的内容区域分别处理。字段表不因没有重复记录而被排除，普通文本也不因被放在格内就成为字段。独立标注与验收应覆盖真实数据表、网格排版及混合区域，防止把排版网格错误语义化。

### 3.2 已确认数据表的表达

已确认的数据表完整表达来源内容及其关系，不以“二维比较有用”为理由在最终正文保留表格。字段型按主体或分组组织属性，记录型逐条组织主体与完整属性，比较矩阵按项目和完整比较维度展开；混合结构先区分正文布局、数据表和图片，再分别处理。

每个值在表达前关联完整行列标题路径、单位、期间、适用范围、附注及来源单元格。来源没有给出、不适用、识别缺失、程序尚不支持和关系冲突分别记录，不凭指标名、数值或模板补造限定语。标签和值从来源读取，连接词与列表层级由渲染器生成。

零、真实空白、破折号、跨度占位和识别缺失不能相互替换。跨度表达的是共享属性、分组标题或说明范围时，应保留对应关系，不能把占位空格输出成多个真实空值。内部换表头、单位变化与跨页继承分别限定作用域，不能对整张表套用首组标题。

跨页表先保留物理来源，再证明完整标题、跨度、单位和延续范围，建立逻辑关系。重复标题只从最终叙述中去重，来源证据保持；不能靠相似首行、同列数或相邻位置补标题。跨页关系未确认时分别描述已确认部分，明确未解决的范围，不把两个片段合成确定事实。

以下为格式示意，不是本项目已测原件或新实验结果：

```markdown
## 公司基本情况

- 股票
  - 简称：示例公司
  - 代码：000000
- 联系人
  - 董事会秘书
    - 姓名：张某
    - 电话：010-00000000
  - 证券事务代表
    - 姓名：原表留空

## 主要财务指标

- 营业收入
  - 单位：万元
  - 2025 年度：1,234.50
  - 2024 年度：1,100.00
- 总资产
  - 单位：万元
  - 2025 年末：8,000.00
  - 2024 年末：7,500.00
```

示例中的单位和期间只适用于各自项目，不能扩散到其他指标。比较值和来源已给出的增减值可完整抄录，不在转换阶段重新计算。公司消歧、指标归一、控制权判断与事件抽取继续属于下游。

## 4. 图片引用与可选识字

图片在正文中有明确去向，图题和相邻说明不因图片提取而丢失。以下仅为包内引用格式示意，不是实际解析结果：

```markdown
## 审批流程

![审批流程原图](../assets/approval.png)

- 图中文字（仅在已请求并完成 OCR 时附加）：提交申请；审核材料；完成办理。
```

正文不生成来源未提供的摘要，也不把识字结果展开成节点和流转关系。图片缺少图题时使用“插图”等中性名称；不以 OCR 是否成功替代图片是否完整交付的检查。

## 5. 图片处理的范围边界

流程图、组织结构图、统计图表与照片统一按图片保全和交付，不要求生成语义描述、结构化关系或自然语言解图。当前不开发相应模型、关系层、独立节点或连线标注、评价指标及验收任务。若以后改变范围，需要另行明确任务，不能作为本契约的隐含后续工作。

图片中的来源文字和图题照实保留；外部下游如需理解图意，可直接消费交付图片。数据表转换与图片语义化是不同范围：来源已确认为数据表的内容仍按第 3 节处理；仅有图片或未知布局时，不凭视觉外形、文件类型或后端标签强行建立表格关系。

## 6. 页码、页眉与页脚清理

物理页号、重复文档抬头、页边重复导航和页脚属于最终输出清理对象，原始位置、文字与判断依据留在证据层。清理依赖页面角色、重复范围、版面位置和正文上下文，不根据顶部、底部或一段纯数字直接删除。

业务标题、真实章节编号、表内期间、金额、单位、附注、法律声明、签章、签字和日期即使出现在页边也须保留。页脚中的业务说明应移入对应语义范围；重复的文档标题在需要时保留为正文标题，去掉的是逐页重复副本。

清理后的最终文字正文不出现物理页分隔注释、页眉页脚角色注释或独立排版页码。页码仍可在内部来源定位使用；原文句子中有业务意义的编号或页码引用不能无条件删除。保留图片的源像素不要求被改写以抹去原图中附带的页码；图片保全与文字清理分别检查。无法可靠区分业务内容与页面家具时记录未解决状态，并保留内部证据，不能以误删业务内容换取形式通过。

## 7. 未完成、失败与覆盖

来源解析、内容分类、数据表转换、正文清理和图片交付分别记录覆盖。来源中的数据表、网格排版、图片及混合区域与最终去向逐项对应，漏检也属于未覆盖，不能只统计已检出片段。图片未语义化不属于失败或未覆盖项；未请求的 OCR 不记作失败。

范围内的内容未完成时，内部保存原表、原图、候选和原始文本；部分文档说明已确认内容、未解决范围及原因。数据表转换不支持、网格用途或顺序未确认、文字未识别、来源关系冲突、图片遗漏与原件不可辨分别列明，不能删内容取得形式通过，也不能混入原始表格伪装为转换成功。

HTTP 200、`/ready`、既有 Job `completed`、文件可下载和表格被删除都不能证明最终转换完成。语义不完整必须与既有 `partial` 等任务状态一致关联；2026-10-29工作区已将未完整转换的表格传递到文档结果partial，线上Job状态及完整接口链路仍以实际部署和验收为准。来源保全成功与语义完成分别报告，未知不算正确，也不算零成本。

## 8. 最终转换与验收

最终转换在来源解析、内容分类、数据表关系关联及必要资产处理之后执行。在线与持久正文保持字节一致，输出包仅按第 1.2 节适配资产路径。MO-Parse 接入不同后端后履行同一公开契约；研究比较无需调用这段转换或直接输出最终格式。

- 先对照本管线原生输出核对适配：结构、媒体、顺序、来源、角色及失败不丢失；再检查服务最终内容，适配错误与解析错误分别记录。
- 清点数据表、网格排版、混合区域和图片，核对内容去向及分类依据；错误地把排版网格变为字段记录属于转换错误。
- 对数据表关联和渲染使用受控结构检查，再以真实完整 PDF 核对标题、单位、期间、附注和跨页范围；网格排版另查正文顺序及是否虚构关系。这些测试不是候选解析管线的前置要求或能力成绩。
- 检查文字正文没有 GFM 或 HTML 表格、XML 区域定义、物理页码、页眉页脚、分页标记及完整坐标调试块；允许图片引用及已请求的 OCR 文字，不检查图片语义关系。
- 检查正文阅读顺序、段落连续性、有效标题、签章日期和业务附注完整；清理页面家具不能降低内容保全。
- 分报格式、数据表语义覆盖、布局正文保全、图片覆盖、来源引用、未解决范围和状态；转换费用与解析费用分开，不混入管线排名。
- 核对 ZIP 包含 `result.md`、清单和全部引用图片，解压后相对路径可用且无需连接服务；资产校验值正确，包内正文与在线正文仅存在声明的图片地址映射差异。无图文档也能打包。
- 用完整原件验证响应、持久 Markdown、下载和资产一致；内部来源证据可追溯，诊断与业务正文分离。

## 9. 当前实现差距与迁移

2026-10-31工作区修复partial剩余片段的来源跨度显示，并将已有明确附注绑定的文本数学标签转写为可直接阅读的标签及附注标记。两项改变均进入实际正文；没有扩展到数学公式解释、未知分组恢复或全部网格正文转换。软件验证、冻结候选回放及逐页内容验收分别记录在[评测索引](../../benchmark/reports/README.md)，尚未部署。

2026-10-30工作区增加P07/P08原生单元格结构入口和局部业务范围转换，采用来源支持的标量比较或明确会议记录字段，输出各记录的表题、期间、单位与本表附注。PDF完整格网不再是唯一前提，P08仍只读原生视觉结果；来源冲突、结构缺失及丢失的层级继续保留未解决。制作信息仅按明确footer角色及制作字段清理，法律说明与签署日期保留。受控结构测试、完整回放和真实内容判断分别记录；该实现尚未部署，结果及采用结论见[评测索引](../../benchmark/reports/README.md)。

当前表格语义实现支持矢量网格和显式单元格分区的来源绑定、部分多层期间与行分组、明确短字段关系，以及按安全源行保全的partial转换。原生正文增加有区域归属的选择与有限遗漏恢复，但未覆盖全部复杂读序。2026-10-29工作区增加共同最终正文步骤，移除生产者内部物理页标记、分页控制、表格诊断注释及处理统计，采用P07和P08原生明确且可唯一定位的相邻正文续接，并按受限原生角色清理页码和重复页眉；审计文字和精确编辑记录单独保存。业务否定、实体名称、期间、金额、单位和签章不得通过改写、推理或清理补齐。未解决表格仍保留GFM或具有真实跨度的HTML及部分无法确定角色的页面家具，并传递partial，尚未满足所有材料的最终契约。`semantic-view`、`semantic-source`、`semantic-retained`、`semantic-summary`及[表格来源与证据约定](table-source.md)继续用于内部转换和来源审计，不划分内部协议版本。工作区能力、实际评测及线上部署分别记录。

当前 PDF 资产路径保存后端检测到的图片区域，扫描或混合页可保留整页来源图；未检出的嵌图、完整矢量图形及正文原位引用覆盖尚需验证。`describe_images` 默认关闭，开启时仅做可见文字识别；没有图片语义化不再属于缺口。

现有 [StorageService.build_bundle](../../app/services/storage_service.py) 只写入当前清单和资产文件，尚未包含 `result.md`，也未提供包内正文的相对图片引用，因此当前 `bundle` 是资产包，还不是第 1.2 节约定的完整输出包。当前清单使用既有 `schema`、`content_id`、`source_sha256` 和资产元数据，并排除资产位置；没有上述 `markdown` 和 `source_map` 信息。本文补齐目标，不修改打包代码、公开协议字段或历史 ZIP；可选映射未实现不单独算作打包失败。

上述是当前实现差距，不先据现有有限代码设计八组共同出口。落实顺序为：先确认每组完整原生输出与媒体，逐组说明并验证适配逻辑，再研究用途判断和数据表转换，最后设计共同组装、清理、状态传递及完整输出包。各组格式核实程度、已知传输损失与待实现项只在[输出与适配说明](../pipelines/README.md)维护，实施依赖见[技术路线](../engineering/technical-route.md#2-实施阶段与交付物)。

解析预期结果与语料生成由外部项目承担。真实内容验证需明确交接版本化原件及数据表、网格排版、混合区域、图片和页面家具的独立标注。格式样本验证、适配信息保全、转换正确性和完整服务验收分别记录；图片语义化不在范围。2026-10-29的实现及配对评测复用已保存原生产物，不新增模型推理或部署，冻结参考保持原样。
