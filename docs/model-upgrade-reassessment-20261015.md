# Docling 与表格模型复测（2026-10-15）

> 后续比较统一维护在[完整报告](../benchmark-results/clean-model-comparison-20261015/report.md)：包含移除旧补偿的模型组合实验、历史 Paddle 候选及当前线上完整管线各 10 份／502 页的真实 HTTP 验证。本文保留上一阶段的配置、范围和证据。

“新版都退化”的早期结论已经撤回。初轮统计把源 PDF 的原生网格列索引、空列和
rowspan/colspan 的完全相同当作金额与期间绑定正确性；删掉空列或调整多级头表达
也会扣分。另有全表结构门禁把局部问题扩成整表零分。这些指标可以衡量结构忠实度，
不能单独证明最终 Markdown 金额错列或模型整体变差。

还发现一次隔离测试配置错误：将 SDK 地址映射到主机 12302，该端口实际属于
另一项服务，健康检查虽返回 `status=ok`，实际 SDK 解析 POST 全部 404。该轮
完整 10 份／502 页已保留为 `CONFIGURATION_ERROR` cohort，不具备扫描后端
等价性，尤其 119 页文件第 8 页财务损坏不能据此归因新版库或模型。主服务在
这两轮模型比较期间没有被修改。真实 SDK 的容器地址和生产实际 URL 已另行
核对，并用原件第 8 页真实 POST 取得 200、布局区块及 58×8 原始表格，再启动
全语料重跑。不能以 `/ready` 代替解析路由验证。
错误配置、76 次 404 调用及实际路由证据保存在
`http-evaluation/http-corpus/routing-configuration-error/`，原输出不覆盖。

原始输出、初轮统计和原件 gold 均保留。复测分别检查完整表头及列义、金额的原件
行和期间归属、单位、真实缺字、合并跨度和原生网格一致性；全文出现数字不能代替
正确绑定。没有根据营业收入等指标名称推断期间，没有在模型评测中补入原件答案。

## 候选与公平配置

- 旧库：Docling 2.119.0、docling-ibm-models 3.14.0。
- 新库：Docling 2.139.0、docling-ibm-models 4.0.3。
- 两组分别比较 TableFormer V1 Accurate 与新的 TableFormer V2 权重，并分别记录
  `do_cell_matching=True/False`。V2 是预览模型，新版 Docling 默认仍为 V1。
- 固定 V1、V2 和布局模型快照，保存所有实际读取文件的 SHA；相同组采用相同 PDF、
  模型、CPU、线程和匹配配置。原始上游比较与应用兼容环境的完整依赖清单分别保存，
  不把 Transformers 5.19.0 和 5.8.1 的运行组说成完全相同环境。
- 原始模型比较不调用 MosaicParse、原生网格恢复、GLM 或 Qwen。另用复制的应用
  建立隔离 HTTP 服务，仅将原生网格恢复替换为有逐调用证据的 noop；其余融合、
  跨页合并及删头路径与当前应用相同。公开接口保持一致。

官方版本来源：[Docling 2.139.0](https://github.com/docling-project/docling/releases/tag/v2.139.0)、
[IBM models 4.0.3](https://github.com/docling-project/docling-ibm-models/releases/tag/v4.0.3)、
[TableFormer V2](https://huggingface.co/docling-project/TableFormerV2)。
Z.ai [GLM-OCR SDK 0.1.5](https://github.com/zai-org/GLM-OCR/releases/tag/v0.1.5)
已经是当前服务所用版本；[官方权重提交](https://huggingface.co/zai-org/GLM-OCR/commits/main)
尚未确认新的代际权重。SDK、第三方 Docling 插件、模型权重需要分别判断。

`-7,735,172.19` 负号缺失均直接出现在原始模型/后端格中。后面的真实 HTTP
组使用应用兼容环境 Transformers 5.8.1，两组运行环境、输入范围及分母分别记录。
