# ADR-0001：以忠实的逻辑表 GFM 作为文档内容与下游抽取边界

- 状态：已采纳并实施
- 日期：2026-09-15
- 决策范围：PDF 表格恢复、公共内容格式、下游实体/关系/事件/财务指标抽取
- 对应实现：`9481d60 feat: simplify parsing output to GFM Markdown`
- 取代的实验性方案：公开 `DocumentEvidenceIR`/坐标 JSON、
  `mosaic-semantic-markdown/1.0`、`semantic-table`/`<fact />`

## 背景

MosaicParse 的下游目标不是复刻 PDF 的像素布局，而是帮助 LLM 正确抽取实体、关系、
事件和财务指标。不过，PDF 表格并不是稳定的二维数组：

- 一张逻辑表可能跨页，续页可能重复表头，也可能省略表头；
- 同一张表中可能先使用“本报告期末/上年末”，中途再切换为
  “本报告期/上年同期”；
- 合并单元格在表格识别后可能被拆开、重复传播或错配到相邻行列；
- 左右两张子表可能在页面上并排，却被识别成一张宽表；
- 标题、单位、脚注、说明和签章 OCR 可能被塞进表格；
- 扫描、旋转、印章遮挡和 OCR 错字会破坏数值与行标签、期间的归属关系。

因此，“识别出一个表格网格”不等于“理解了表格语义”。如果在上游证据仍不可靠时，
立即把单元格改写成带确定字段名的列表或 XML，错误会从可见的结构歧义变成看似可靠的
业务事实，下游模型反而更难纠正。

本 ADR 回答三个问题：

1. 解析层应怎样恢复表格，才不会放大识别错误？
2. MosaicParse 应向下游提供 GFM、文字列表、semantic XML、坐标 JSON，还是页面图像？
3. 如果以后训练小模型，它应预测表格内容，还是只预测结构？

这里的 GFM 指 GitHub Flavored Markdown。GFM 表格语法只能把第一行正式声明为表头，
但它仍可忠实保留中途出现的第二组表头文字。

## 决策

### 1. 唯一公共文档结果是 GFM Markdown

MosaicParse 对外只返回和持久化 `result.md`。它保留标题、段落、列表、单位、表格、
原始单元格顺序和可确定的跨页连续关系。

解析层不再：

- 按“财务指标、股东、债券、公司属性”等领域类型对表格硬编码分型；
- 把表格改写为 `semantic-table`、`<fact />` 或其他 semantic XML；
- 根据第一行表头为后续所有行生成 `current_period`、`prior_period` 等字段；
- 返回或持久化包含正文、表格、bbox 和单元格坐标的文档 JSON。

Job 状态、错误、SSE 事件和无坐标资产清单仍可使用 JSON。它们是控制协议，不是另一份
文档内容结果。

### 2. 解析证据留在内部，业务语义留给下游

页面坐标、单元格 bbox、rowspan/colspan、候选来源和质量诊断仍保留在单次请求内部，
用于：

- 阅读顺序恢复；
- 页面方向判断；
- 表格行列和合并关系恢复；
- 跨页逻辑表合并；
- 低置信度单元格的局部图像裁剪；
- 质量门控和告警。

这些内部证据不进入普通下游 prompt，不作为公共结果持久化。MosaicParse 负责“页面上
可见什么、结构如何”，EventRail 等下游负责实体消歧、业务关系、事件 ontology、财务
指标归一化和事实去重。

### 3. 下游按逻辑表或章节切块，不输入整份百页文档

推荐链路为：

```text
PDF / Office / 图片
  -> 原生文本、OCR、TableFormer/GLM 表格恢复
  -> 可确定的旋转、左右子表拆分、跨页逻辑表合并
  -> 忠实 GFM Markdown
  -> 按逻辑表/章节切块，携带标题、单位和邻近说明
  -> 下游 LLM（reasoning=none）抽取结构化事实
  -> 将已抽取事实渲染为清晰的 Markdown 列表
```

文字列表适合人读和最终展示，但不作为表格识别与事实抽取之间的强制中间格式。

### 4. 页面图像只用于局部疑难复核

数字原生 PDF 使用原生文字与 Docling Layout/TableFormer。扫描页先方向归一化，再使用
PP-DocLayoutV3 与 GLM 表格识别。只有质量门控定位出的少量冲突行才附加局部裁剪图；
局部结果未通过同一组不变量时整次回滚。签章页和整表 Qwen 默认关闭；整表拓扑确实
无法恢复时保留最佳 GLM/Docling 候选和告警，全表视觉只作为显式实验/救援开关。

Qwen 不参与 GFM 到语义列表/XML 的转换。当前解析器中的可选 Qwen 路径只读取局部或
全表像素证据，修复低置信度视觉结构；它不是业务事实抽取器。`VLM_ENABLED=0` 可完全
关闭 Qwen，三个 PDF 子路由开关分别控制签章页、整表和局部复核。

### 5. 暂不训练“生成语义列表”的小模型

如后续确定性规则仍无法稳定恢复复杂拓扑，小模型的目标应严格收缩为结构预测：

- 表头行范围和表头作用域；
- 数据行、分组标题、说明行、合计行等行角色；
- 左右并排子表的拆分边界；
- 跨页 continuation 关系；
- 合并单元格对后续行的归属；
- 对原始 `cell_ref` 的引用关系。

模型不得复制、改写或生成数值，也不得直接生成自由文本或业务事实。所有内容值仍从
原始单元格复制。是否训练该模型，要由更大、双人复核的 Gold 上相对确定性基线的增益
决定。

## 评测口径

### Gold 与指标

主要抽取消融使用 3 个真实表格样例：

| 样例 | 类型 | Gold 行 | Gold 数值 |
| --- | --- | ---: | ---: |
| `1225475375.pdf` 第 8 页 | 横置扫描、左右并列表 | 45 | 87 |
| `1225475642.pdf` 第 9 页 | 普通扫描、左右并列表 | 53 | 99 |
| `1225474693.pdf` 第 3 页 | 原生 PDF 财务指标表 | 8 | 23 |
| 合计 |  | 106 | 209 |

一个数值只有在“规范化行标签、期间槽位、数值”同时匹配 Gold 时才算正确。数字抄对但
放错行或错列仍计错；额外抽取的数字会降低 precision。

扫描样例的文本候选来自方向归一化后的 GLM 表格网格，原生样例来自
Docling/TableFormer。表示形式消融的上游不调用 Qwen，Qwen 只作为下游抽取器，从而
避免“Qwen 修表后再由 Qwen 抽取”造成的自证循环。

Gold 和绑定感知评测器保存在访问受控的本地回归语料中：

- `pdf_sample/gold/table_fact_gold_v1.json`
- `pdf_sample/gold/evaluate_table_fact_ablation.py`

真实 PDF、Gold 和逐次模型输出因授权与体积原因不提交 Git；本 ADR 保存可公开的聚合
结论。当前 Gold 为单人复核的临时 Gold，因此所有结果只支持架构选择，不构成普适精度
承诺。

## 实验结果

### 实验 A：提前生成语义 XML 会不会改善抽取

在 6 页 `1210860446.pdf` 的 57 条财务观测上，首次对照结果为：

| 输入 | 正确观测 |
| --- | ---: |
| 原始 GFM | 57/57 |
| 无损文字列表 | 57/57 |
| 无损 XML | 57/57 |
| 当时的 `semantic.md` 编译结果 | 42/57 |

`semantic.md` 转换器只读取第一行表头，并把它应用到后续所有数据行。当表中第二组表头
从“本报告期末/上年末”切换为“本报告期/上年同期”时，转换器删除了原始第二表头，
再写入错误的 `current_period` 等确定字段。

原始 GFM 的语法树虽然没有把中间行声明为第二个表头，但表头文字仍在字符序列中，
下游模型可以利用内容恢复作用域。结论不是“GFM 没有结构问题”，而是：

> 保留原始信息中的可见歧义，通常比提前写入错误且看似确定的语义更安全。

### 实验 B：Qwen 能否直接接收 PDF

当前 Ollama/OpenAI-compatible Qwen 服务不能直接接收 PDF 文件：

- Chat Completions 返回 HTTP 400：`invalid message format`；
- Responses/File 返回 HTTP 400：`file inputs are not currently supported`。

因此没有“原始 PDF 文件直传”的准确率。最接近的对照是把同一 6 页 PDF 以 2.5 倍
渲染为六张图片，一次性输入模型：

| 输入 | 正确观测 | 输入 tokens | 模型耗时 |
| --- | ---: | ---: | ---: |
| 六页原图 | 57/57 | 20,158 | 39.98 s |
| 解析后 GFM | 57/57 | 5,814 | 18.83 s |
| 解析后文字列表 | 57/57 | 5,965 | 19.83 s |

页面渲染另需 1.88 秒，所以视觉路线总计约 41.86 秒。该样例上图片没有提高准确率，
模型耗时约为 GFM 的 2.12 倍，输入 tokens 约为 3.47 倍。

此处 57/57 只覆盖指定财务观测，不代表文档内所有文字、债券、股东关系和事件均为
100%。

### 实验 C：三类表格、四种表示的单轮探索

首轮扩大到 3 个样例后，正确绑定结果为：

| 样例 | GFM | 文字列表 | XML | 整页图 |
| --- | ---: | ---: | ---: | ---: |
| 横置扫描并列表 | 85/87 | 85/87 | 85/87 | 39/87 |
| 普通扫描并列表 | 98/99 | 98/99 | 98/99 | 98/99 |
| 原生 PDF 表 | 23/23 | 23/23 | 23/23 | 23/23 |
| 合计 | 206/209 | 206/209 | 206/209 | 160/209 |

三种文本形式都继承了上游网格中的 3 个错误；列表和 XML 没有凭空恢复丢失的视觉证据。
整页图在横置密集表上的结果明显更差。

首轮合计耗时为 GFM 129.9 秒、列表 115.8 秒、XML 78.9 秒、整页图 166.3 秒。
由于当时没有严格关闭推理，且单次生成波动明显，这组时间只用于发现问题，不用于最终
性能决策。随后进行了固定配置的五轮复测。

### 实验 D：关闭推理后的五轮表示消融

配置：

- 模型：`qwen3.8:latest`，当时驻留版本为 27.3B、Q4_K_M、32K context；
- 3 个样例 × 4 种输入 × 5 轮，共 60 次正式调用；
- `temperature=0`、`reasoning_effort=none`；
- 串行执行，每轮改变 nonce，降低重复提示缓存干扰；
- 两次预热不计入统计；
- 所有正式响应的 `reasoning_chars=0`。

下表中的耗时和 tokens 是每轮 3 个样例的合计：

| 输入 | 五轮正确绑定 | 成功率 | 耗时 P50 / P95 | 每轮输入 tokens |
| --- | --- | ---: | ---: | ---: |
| GFM | 206、207、207、206、207 / 209 | 15/15 | 45.5 / 46.8 s | 6,365 |
| 文字列表 | 每轮 206/209 | 15/15 | 41.4 / 41.5 s | 11,150 |
| XML | 每轮 206/209 | 15/15 | 43.4 / 48.5 s | 15,618 |
| 整页图 | 前四个完整轮次均为 187/209 | 14/15 | 79.6 / 85.0 s | 12,619 |

文字列表的耗时中位数比 GFM 少约 4 秒，但 GFM 的输入 tokens 比列表少约 43%，比 XML
少约 59%。XML 没有准确率收益，也没有稳定的延迟优势。

整页图还有三类额外问题：

- 横置扫描表前四轮均只有 66/87；
- 原生页虽然命中目标表 23/23，却从同页其他表多抽取 31 个数值，候选数从 23 增至
  54，绑定 F1 只有 59.74%；
- 第五轮横置页在生成 8,000 tokens 后以 `finish_reason=length` 截断，形成无效 JSON。

#### GFM 保留歧义的实际价值

横置扫描表的源网格包含错位行：

```text
短期借款 | 空 | 五、（十九） | 100,000,000
```

GFM 五轮结果为 85、86、86、85、86 / 87。三轮中，Qwen 根据“`五、（十九）` 更像附注”
把 `100,000,000` 移回本期列；另外两轮忠实保留物理错列。

列表/XML 在生成时已把错误固化为：

```text
note=""
current="五、（十九）"
prior="100,000,000"
```

所以五轮均停留在 85/87。GFM 的偶发自修正不能作为可靠修复能力，但证明过早生成字段
会堵死下游利用上下文纠错的可能。源结果完全缺失的上期值 `142,000,000`，三种文本
形式都无法恢复。

### 实验 E：跨页、多表头专项

`1210860446.pdf` 的跨页财务指标表包含 10 行，并在表内切换期间表头。使用同样的无推理
配置，对三种文本表示各运行 5 次：

| 输入 | 完整语义行 | 期间/数值绑定 | 耗时 P50 | 单次输入 tokens |
| --- | ---: | ---: | ---: | ---: |
| GFM | 五轮均 10/10 | 五轮均 60/60 | 4.878 s | 481 |
| 文字列表 | 五轮均 10/10 | 五轮均 60/60 | 4.924 s | 606 |
| XML | 五轮均 10/10 | 五轮均 60/60 | 4.900 s | 655 |

即使第二组表头在 GFM 语法上只是普通数据行，Qwen 在该提示与样例中五轮都正确识别了
表头作用域变化。这个结果验证了“忠实保留第二表头”足以支持当前下游，但不意味着任意
模型、任意残缺表头都能稳定推断。

### 实验 F：上游表格识别与视觉修复消融

本实验评估的是“像素到可信单元格网格”，不是 GFM/List/XML 表示。扫描集包含 2 页、
98 行和 186 个数值：

| 解析链路 | Schema 行正确 | 数值正确绑定 | Numeric F1 | 墙钟合计 | Qwen |
| --- | ---: | ---: | ---: | ---: | ---: |
| Docling 扫描基线 | 0/98 | 0/186 | 0.00% | 80.770 s | 0 |
| GLM SDK，横置页未先旋正 | 9/45 | 50/87 | 55.25% | 17.124 s | 0 |
| GLM SDK，先做方向归一化 | 96/98 | 183/186 | 98.65% | 33.250 s | 0 |
| 当时的完整 Qwen 融合 | 97/98 | 184/186 | 98.92% | 209.242 s | 6 次 / 89.580 s |
| 旋正 GLM + 两次局部 Qwen + 确定性归一化 | 98/98 | 186/186 | 100.00% | 约 36.306 s | 2 次 / 约 3.056 s |

Docling 扫描基线的 0 分只表示没有形成可计分的行列网格；扁平 OCR 中存在部分数字，
但不能证明它们与行标签和期间的绑定。

关键发现：

- 方向归一化贡献了绝大多数提升；
- 对所有扫描表执行完整 Qwen 成本很高，只比旋正后的 GLM 多修正 1 个数值；
- 合计/小计和列类型校验可以定位少量冲突，再用行级裁剪复核；
- 原生 `1225474693.pdf` 第 3 页由 TableFormer + 原生文本达到 23/23，约 6.0 秒，
  无需调用 Qwen。

因此视觉模型应是受质量门控的局部证据工具，不是每页默认解析器，也不是语义格式转换器。

### 实验 G：原生 PDF 页级并行

同一份 6 页原生 PDF 在 CPU Docling/TableFormer 路径上的实测：

| 配置 | 墙钟 |
| --- | ---: |
| 1 个 converter × 4 threads | 22.73 s |
| 2 个 converter × 6 threads | 12.44 s |
| 3 个 converter × 4 threads | 12.12 s、11.97 s |
| 4 个 converter × 3 threads | 13.49 s |

所有配置在去除动态 `content_id` 后输出一致，规范化 SHA-256 为
`a1b6c71ca14a024c5f4cd789a40af7518936d6fe9b6473bc5d7e683705873d81`。

最终采用 3 × 4，并只对原生文本充足、连续且达到最小页数的 PDF 启用。扫描、混合、
稀疏选页和短文档保持串行，避免并行放大远程 OCR/VLM 调用。

11.97 秒只证明相同内容下的性能改进，不代表表格语义准确率为 100%。

### 实验 H：历史整文档回归与 Evidence IR 原型

早期 `accurate/auto_visual` 路径曾运行 10 份、共 502 页真实 PDF：累计 Job 时间
3,527.344 秒，得到 398 个 trusted、54 个 degraded、50 个 untrusted 页；52 页进入视觉
融合，共调用 Qwen 102 次，仍有 82 个未解决来源冲突。两份长文档分别耗时 890.592 秒和
1,260.429 秒，后者明确超过当时 900 秒默认整文档时限。

这组旧契约结果说明：

- “调用更多视觉模型”不等于消除全部结构冲突；
- 全文档、全页面视觉处理的尾延迟和失败面不可接受；
- 应优先确定性修复、逻辑表切块和局部复核。

另一个原型曾把 `DocumentEvidenceIR` 坐标 JSON 作为主产物。它证明 bbox、单元格来源和
候选证据对跨页合并、质量判断及审计有用，但没有证明把完整证据 JSON 交给业务 LLM 会
提高事实抽取质量。该方案最终调整为“Evidence IR 仅限请求内部，公共结果为 GFM”。

上下文成本实测也支持这一边界：`1225475375.pdf` 第 8 页的完整 IR 约为 38.5K tokens，
对应的阅读 Markdown 约为 1.76K tokens，相差约 22 倍；旧版长文档 `metadata.json` 约为
349K–528K tokens，已经不适合直接进入普通业务抽取上下文。这是输入成本测量，不是
“JSON 抽取准确率更低”的实验证明。

历史报告位于本地访问受控语料目录：

- `pdf_sample/parsed_results/REPORT.md`
- `pdf_sample/evidence_ir_results/REPORT.md`
- `pdf_sample/results/QWEN_INCREMENT_ABLATION_20260913.md`

这些报告对应旧版本和不同结果契约，不能与当前生产版本的绝对耗时直接横向比较。

## 备选方案与取舍

| 方案 | 决定 | 原因 |
| --- | --- | --- |
| 忠实逻辑表 GFM | 采用 | 最紧凑；保留原始表头和歧义；五轮零失败；人和 LLM 均可读 |
| 抽取前文字列表 | 不作为默认中间层 | 可读，但更长；依赖正确列映射；可能提前固化错列 |
| semantic XML / `<fact />` | 删除 | 最长；无准确率收益；错误字段具有虚假确定性；不直观 |
| 完整坐标 JSON / Evidence IR | 仅内部保留 | 对解析与审计有用，但不适合作为普通业务 LLM 输入 |
| 原始 PDF 直接输入 Qwen | 不可用 | 当前服务接口不支持 file/PDF 输入 |
| 整页图默认输入 | 拒绝 | 慢、tokens 多、混入无关表、横置密集表效果差且可能截断 |
| 局部裁剪图 | 条件采用 | 在质量门控已定位冲突时，以很小成本补充缺失视觉证据 |
| 领域规则硬编码语义表 | 删除 | 规则无法覆盖多表头、跨页、并列表和说明行，错误难以察觉 |
| 立即训练语义列表模型 | 推迟 | 当前没有比 GFM 更好的证据；模型目标会诱导内容改写和幻觉 |
| 训练只预测拓扑的小模型 | 保留为后续选项 | 可以减少硬编码，但必须先扩大结构 Gold 并证明稳定增益 |

## 结果与影响

### 正面影响

- 公共契约收敛为一种内容格式，API、前端、MCP 和存储更简单；
- 不再把解析器猜测伪装成规范化财务事实；
- GFM 最紧凑，降低下游 context 和传输成本；
- 原文、第二表头和异常单元格仍可见，便于模型或人工发现问题；
- 解析层与 EventRail 的业务 ontology、修订和训练反馈保持清晰边界；
- 内部坐标能力仍支持跨页、裁剪和质量诊断。

### 代价与风险

- GFM 本身不能完整表达任意多级表头、rowspan/colspan 和表头作用域；
- 下游切块器和抽取 prompt 需要理解表内表头切换；
- 原始网格漏掉的内容无法仅靠文本表示恢复；
- 当前 Gold 规模小，不能据此宣称对所有 PDF 或模型普适最优；
- 可选视觉修复与下游使用同一模型时仍可能产生相关性，因此评测必须保留“上游无 Qwen”
  基线，并分别报告解析层和抽取层指标。

## 后续工作

1. 扩大 Gold，并按原生、扫描、横置、印章遮挡、多级表头、无线表格、跨页表格、
   rowspan/colspan 和说明文字混入分层。
2. 关键样例使用双人复核，记录分歧与裁决，不再以单人临时 Gold 作为发布精度。
3. 把“行标签 + 表头作用域/期间 + 数值 + 单位”作为核心指标，不能只计算 OCR 字符或
   数值命中率。
4. 为逻辑表切块增加回归：携带章节标题、单位、邻近说明和来源页，不传整份百页
   Markdown。
5. 持续比较纯 GLM 基线、局部视觉复核与显式启用的全表实验，分别报告调用数、增益、
   P50/P95、截断和未解决冲突；默认配置下签章页和整表 Qwen 调用必须为零。
6. 只有在结构 Gold 上证明确定性方法不足且小模型有稳定增益时，才训练表头作用域、行
   类型、左右子表拆分、跨页延续和单元格归属模型。
7. 所有未来表示实验必须固定模型版本、temperature、reasoning、调用顺序和预热状态，
   至少重复五轮，并分别报告失败率、precision/recall/F1、tokens 与墙钟时间。

## 一句话结论

> MosaicParse 应输出经过解析层结构恢复、但未经业务语义改写的逻辑表 GFM；让下游模型
> 从忠实、紧凑、可追溯的内容中抽取事实，再把事实渲染成列表。内部坐标用于解析，XML
> 不再作为接口，整页视觉只用于受控兜底，小模型若训练也只预测拓扑、不生成内容。
