# ADR-0001：面向信息抽取的 Markdown 与图片交付

状态：2026-10-19 采纳表格语义输出目标，2026-10-21 收敛图片范围并恢复完整输出包要求。本文保留决策背景，当前规范统一见[输出契约](../specs/moparse-output-spec.md)。

## 背景

最早的 GFM 输出边界没有覆盖数据表的语义关联，后续目标又将任意流程图和组织结构图的关系恢复设为交付条件，同时把图片降为可选内部证据，遗漏了正文与图片一起返回的输出包。原来的“全部表格”表述也容易把用于排版的网格误当成数据表。

## 当前决策

确认的数据表仍做有来源的语义转换；先区分数据表、网格排版与未知区域，不能凭格线或解析器标签建立语义关系。图片语义化明确排除，不保留为待实现目标；图片文件、正文引用和来源图题是有效交付。

交付以一份 Markdown 正文和关联图片为基础，完整输出包将正文、图片及清单一起返回。格式、离线路径、状态与验收只在[输出契约](../specs/moparse-output-spec.md)定义，不在本 ADR 复制。

## 实施影响

2026-10-21 进一步明确集成设计顺序：先核实每条完整管线的原生结构、媒体与失败，再说明其适配逻辑，最后设计共同组装。逐组定义集中于[输出与适配说明](../pipelines/README.md)，不以当前有限 IR 或 GFM 显示模型作为所有后端的先验输入要求。

删除重复的项目规格入口与规格正文，执行和维护约束归 [AGENTS.md](../../AGENTS.md)，接口现状归 [API](../specs/api.md)，内部来源证据归[表格来源约定](../specs/table-source.md)，工作顺序归[技术路线](../engineering/technical-route.md)。

现有表格转换、页面清理及完整输出包仍有实现差距；图片未语义化不属于缺口。历史输出、测量与发布记录保持原样，不能以文档修订宣称代码验收或部署完成，也不恢复旧格式兼容分支。

解析研究继续比较八个固定配置的原始内容、结构和实际成本；服务最终格式不作为解析准入条件。实体消歧、指标归一与业务推断继续属于下游。研究方法与历史证据见[研究框架](../research/research-framework.md)，当前任务不启动推理或部署。
