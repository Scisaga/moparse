# ADR-0001：以忠实的逻辑表 GFM 作为文档内容与下游抽取边界

> 历史决策记录：项目于 2026-10-18 更名为 moparse。下文保留当时名称；输出契约继续有效。

- 状态：已采纳并实施
- 初始日期：2026-09-15；配置更新：2026-10-17
- 决策范围：公共内容格式、表格结构恢复及下游抽取边界
- 初始实现：`9481d60 feat: simplify parsing output to GFM Markdown`

## 背景

表格识别后的网格仍可能包含多组表头、跨页延续、合并格、左右并列表和错列。
若在解析阶段按固定首行生成领域字段，错误期间和行列归属会被包装成确定的业务事实。
解析器因此需要忠实保留原件结构和不确定性，让下游结合上下文完成业务抽取。

## 决策

唯一公开文档结果为 `result.md`（`text/markdown`），保留正文、标题、列表、单位和 GFM
表格；不再生成语义 XML、`<fact />`、按领域硬编码的语义表或公开坐标 JSON。

原生页使用 Docling 2.139.0／TableFormer V1 Accurate／matching=False／PyPdfium。
扫描、混合页使用官方 GLM-OCR SDK，先方向预处理，再执行布局与区域识别。结构校验
不会根据指标名称补造期间，也不会用额外通用模型重写缺失或冲突的数值。

跨页表只有在完整表头和列义一致时才能删除重复表头。相同列数、相似布局或部分相同
文字不足以确认续表。不同表头应拆表，或完整保留并明确作用范围；多级表头、合并格、
单位、来源页关联与原始单元格文本均保留。

页坐标、bbox、rowspan/colspan、候选来源和质量诊断只在同一次解析内部使用，用于
阅读顺序、表格恢复、跨页判断和资产处理，不作为普通下游输入或第二份公开文档结果。
资产索引和 Job JSON 是控制协议，不是文档内容接口。

Office 嵌图直接提取；原生 PDF 保留模型检测到的图片，扫描／混合页保留整页来源图，
视频保留采样关键帧。按需文字识别复用 GLM-OCR；`describe_images` 保持参数
兼容性，其内容限于可见文字。视频摘要只列出采样帧的时间戳和识别文字。

推荐下游处理链：

```text
PDF / Office / 图片
  -> 原生文字、表格模型或方向预处理后的 GLM-OCR
  -> 有证据的表格结构恢复与跨页连续关系
  -> 忠实 GFM Markdown
  -> 携带标题、单位、邻近说明和来源页的逻辑表/章节切块
  -> 下游实体、关系、事件和财务指标抽取
```

MosaicParse 负责恢复可见内容及其结构；EventRail 等下游负责指标归一、实体消歧、
事件 ontology、事实去重和修订。解析层不提前替下游生成业务事实。

## 取舍与验证

GFM 紧凑、通用，能保留表内第二组表头；其表格语法无法完整声明任意 rowspan/colspan。
无坐标 HTML 注释附上原模型表头角色、跨度和来源页，未知结构明确标记；可见正文、
空格、重复标签和不确定候选不能静默删除。
内部证据支持结构恢复，但完整坐标对象会增加下游上下文成本，不能替代正确的原件绑定。

模型比较分别报告原值、期间/列义、完整合并格、单位及来源页；数字出现在全文中不算
行列绑定正确。完整发布验收通过真实 HTTP 接口重新处理整份 PDF，核对最终 Markdown，
并记录时间、CPU/GPU 使用、请求、原件哈希和实际部署版本。

完整模型比较和原件实验只在 [report.md](../../benchmark-results/clean-model-comparison-20261015/report.md)
维护；原始输入、标注和逐次输出保存在其证据目录，不在本 ADR 复制过期模型路线。

后续若训练结构模型，目标限于表头范围、行角色、子表边界、跨页关系和单元格引用；
文字及数值始终来自原格。是否采用必须由独立原件标注集上的稳定增益决定。
