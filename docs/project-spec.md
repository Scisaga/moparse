# MO-Parse 产品与工程规格

公开文档结果为普通 Markdown（`text/markdown`），唯一文件为 `result.md`。最终内容以便于下游信息抽取为目标，全部表格、PDF 流程图和组织结构图转换为语义描述，优先采用多层列表；最终正文去掉物理页码、页眉和页脚。规范定义及格式示意见[最终语义输出契约](output-contract.md)。

状态：本文件区分目标要求与当前表格语义实现；文档更新不代表代码或部署已经满足新契约。已有实现及历史发布记录见[运行配方](runtime-recipes.md)，实现差距见[最终契约](output-contract.md#9-当前实现差距与迁移)。

## 1. 产品目标

MO-Parse 恢复可见内容及原件明确表达的关系，生成适合下游直接抽取主体、属性、数值和关系的一份文档。服务负责表达来源已有的信息，实体消歧、指标归一、业务判断、事实去重和事件编排由 EventRail 等下游完成。

当前服务支持 PDF、DOCX、PPTX、图片和视频；解析预期结果与语料生成已在其他项目开展，后续 PDF 研究与验收范围以外部交接的原件、标注版本及明确任务范围为准。流程图与组织结构图的目标适用于 PDF 中相应内容，具体覆盖需核对交接清单，处理层与实现依赖见[技术路线](technical-route.md)；不自动增加输入或扩大到其他格式。

## 2. 输出语义

- 保留业务标题、正文、有效编号、公式、单位、附注、签章和日期，去掉排版页码及重复页眉页脚。
- 所有表格都转换为字段、记录或比较关系的描述；比较矩阵也必须展开，混合表按语义区域分别表达。
- PDF 流程图恢复节点、方向、条件、分支、汇合、回路和必要分组，再使用多层列表组织。
- PDF 组织结构图恢复节点、层级、分组和明确的交叉关系，不能从框线或上下位置自行推导持股与控制。
- 允许短来源引用和按需溯源资产，最终正文不携带原表、HTML 表格、XML 区域定义、完整坐标或分页调试信息。
- 未完成区域明确报告范围与原因，保留内部原件证据；保全原表或原图不算满足最终语义契约。

处理流程为管线原始结果 → MO-Parse 结果转换 → 目标文档，前序步骤可以使用 Markdown、HTML、XML 区域定义或其他原生结构。来源恢复、关系关联与最终转换分离，不要求先生成 GFM。[表格来源与证据约定](table-source.md)只维护来源保全和使用的当前定义，不分内部协议版本；具体显示格式不能决定最终公开格式。

## 2.1 MO-Parse 转换所需的内部信息

本节是 MO-Parse 自身整理和使用的信息，不是候选解析框架必须实现的统一接口。接入代码读取后端原生结果；后端未提供的信息由服务明确缺口并研究补充方法，不能在管线比较时免费补齐。最终接口要求也不约束研究侧原始输出。

| 信息 | 必须保留的内容 |
| --- | --- |
| 身份与来源 | 文档、区域、物理表或图形身份；内部物理页、坐标、原格、节点、连线与原图引用 |
| 表格关系 | 主体、字段和记录边界；完整行列标题路径；值、单位、期间、附注及各自作用范围 |
| 流程关系 | 节点原文、起止端点、方向、条件、分支、汇合、回路、泳道及子流程范围 |
| 组织关系 | 节点原文、分组、层级、来源明确的关系类型、连线标签、比例和附注 |
| 状态与覆盖 | 已确认、候选、冲突、识别缺失、程序不支持、来源不可辨和不适用；各内容与关系的去向 |
| 清理依据 | 页面家具与业务内容的区分依据、清理范围、保留的标题和业务附注及来源映射 |

关系方法输出引用和关系，渲染器从对应来源读取文字与数值。原文没有的信息不能按指标名、公司名、坐标或模板补出。零、真实空白、破折号、跨度占位和识别缺失分别处理；标题及限定语允许有依据复用，不能遗漏或扩散作用范围。

跨页表关系要求完整来源表头、跨度、单位和延续证据；不能因第一行相似或同列数合并。图关系不能按 OCR 阅读顺序替代箭头方向，多层列表也不能将一般图强行变成树；回路、汇合与多重归属使用引用表达。

当前[表格关系模型](../app/models/table_semantics.py)与[语义服务](../app/services/table_semantics_service.py)只实现其中的有限表格能力。当前实现的单位、期间或附注引用缺失表示尚未建立关联，不表示该维度不适用或来源没有信息。流程与组织关系、完整状态模型、最终清理和全结构转换仍需实现。

## 3. 与 EventRail 的边界

表格中的持股记录、图中明确标注的隶属或协作关系属于来源语义，应由 MO-Parse 表达。根据比例、连线或常识推断实际控制关系、组织职责和业务事件属于下游。下游消费最终多层列表与必要短引用，不承担补表头、重建流程连线、删除页面家具或将保留原表改写为事实的职责。

## 4. 当前请求与解析路径

以下为已有公共参数，不是新输出契约已经实现的证明：

```text
file | source_url
scan_policy=auto|skip
unit_range
language
describe_images=false
description_language=zh-CN|en|auto
timeout_seconds
prefer_async                  # 仅 /parse
```

`profile`、`include_renderings` 与旧后端选择参数已删除。服务端 `NATIVE_PARSER_BACKEND` 选择原生后端，扫描与混合页可使用 GLM SDK；MinerU 后不运行独立 Docling 复核。现有来源路由仍待公平质量与成本比较，不能由架构文档宣称最优。

当前 `describe_images` 仅控制已提取图片可见文字识别，未实现流程或组织关系恢复。目标中的必需图形语义转换不应依赖用户额外开启可选图片说明开关；如何衔接现有实现须单独验证，不新增未经实现的请求参数。`scan_policy=skip` 仍保留来源资产，但跳过的应转换内容不能计为满足最终契约。

## 5. 持久化与接口

```text
output/result.md         # 唯一公开文档结果
output/asset-index.json  # 资产访问控制元数据
output/assets.zip        # 按需生成
assets/original/*
assets/derived/keyframes/*
assets/derived/previews/*
logs/warnings.json
```

HTTP 继续使用 `/v1/content/parse`、`/v1/content/jobs`、任务状态、结果、资产、bundle、retry 和取消接口；MCP 继续使用 `parse_content`、`get_content_job`、`get_content_result` 与 `get_content_assets`。详细参数和当前行为见[API](api.md)。本次不增加公开 XML、坐标 JSON 或另一份文档结果。

来源证据可以在任务内部保存，具体保留策略与访问权限由实现维护，不作为普通下游上下文。历史结果保持生成时的字节与 SHA，用于审计，不因此维护旧格式兼容分支或自动迁移。

## 6. 最终转换步骤

最终转换在来源解析、必要资产准备和关系恢复之后运行，清理页面家具、接续正文、组织表格及图形语义，并核对覆盖与来源。同步响应、异步结果、下载和持久化使用同一份最终正文，后续处理不得重新插入来源表格或分页调试块。

现有[解析入口](../app/services/parser_service.py)已将表格语义转换 接在资产处理后，但仍混合语义列表、原表、页面家具及来源注释。当前[表格出口](../app/services/table_service.py)登记精确来源视图，不具备所有表格和图形的最终转换能力。该差距必须通过代码与完整原件验证弥补，不能以改名或格式过滤掩盖遗漏。

## 7. 解析研究与服务验证

[研究框架](research-framework.md)比较各解析方法的原始内容、结构与处理成本，不要求候选实现本规格的服务最终格式。八组采用相同原件、独立标注、忠实导出及资源条件，无需等语义转换、清理或接口功能完成。

MO-Parse 转换另做功能测试：用正确结构与关系隔离关联和渲染问题，再用真实解析结果验证服务内容、页面清理、覆盖和状态。发生错误时检查原件、原始解析、读回、转换、组装和返回文件，按最早出错处归因，不能用服务错误直接给解析方法排名。服务费用单列，不能混入八组解析计时。

外部交接的原件标注与训练/测试划分按完整文档和模板家族分组。预标注经复核后才能进入 Gold，线上纠错进入候选池，不直接回灌。交接清单应说明开发使用情况，已用于开发的原件不属于未见泛化集；本轮不恢复额外六份 PDF，也不自动开展训练。

## 8. 验收

以下验收针对 MO-Parse 服务与公开接口，不是候选管线参与解析对照的条件。

- 最终内容符合[最终契约](output-contract.md)：所有表格、流程图和组织结构图有正确语义去向，正文没有来源表格或页面家具。
- 逐项检查值、完整标题路径、单位、期间、附注、节点、边、方向、条件与组织层级；文字命中、可下载或来源引用存在都不能代替正确性。
- 对零、空白、破折号、跨度、混合区、跨页关系、分支回路、多重归属和页边业务内容分别验证。
- 未支持、识别缺失、不可辨和冲突分别呈现；语义未完成不能冒充完整成功，不能以删除原表取得格式通过。
- 响应、最终持久 Markdown、下载、资产及内部来源证据一致，旧结果不重写。
- 完成适当的代码、接口与真实内容检查；静态检查不代替最终内容验收。

已有表格语义实现的有界组件与接口记录见[实验记录](research-framework.md#101-2026-10-19-表格语义有界实验与实现)。这些记录不覆盖新目标中的全部表格、流程和组织关系及页面家具清理，不构成最终契约通过证据。
