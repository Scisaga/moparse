# MO-Parse：要求结构、业务等价与八组后处理实施

继续执行用户2026-11-06批准的计划。先读AGENTS.md、benchmark/evaluation-tasks.md、moparse_eval/README.md及唯一Lite报告。工作区原有pdf_sample_extra/README.md删除、datasets及benchmark/reference-decisions资料必须保留。

第一门槛是当前Lite授权expected的完整语义要求图。canonical expected及所有语料、映射、页包只读；JSON为程序派生图，XML为同图可读视图，不能手改为第二套答案。要求图须承接原文字面、独立业务命题、限定、必要逻辑关系和精确来源，每个来源分别给T/L/B处置；未知不能变成不适用。独立oracle、遗漏/伪造突变及实际expected文字诊断缺一不可。未经此门槛，不做正式全范围评分或真实候选CPU回放。

当前入口为reference_compiler.py的来源规划、共享语义解释及解释完成后的范围依赖处理，再由requirement_graph.py核对完整性并投影。旧_project_reference_requirements总控已删除，不恢复。Description复合正文、明确引用、父指标归属、完整期间及原始数值来源已有通用读取和独立反例；复杂自然语言仍需继续解释，新组合语法的B/L比较不得因要求图已经编译而自动放行。运行要求图导出前先确认解释器源码稳定，删除失效派生视图后重建，不对旧视图补写完整状态。

当前源码另有独立authorized_source_inventory.py及source_obligations.py：原始授权行段在elements读取前保留，清单不依赖派生图自报范围。重新生成后须同时检查raw传输、角色和局部绑定、关系及partial evidence，不能只看semantic_complete或pending数。正式评分及回放主机均重新绑定canonical；候选worker仅有无答案摘要回执。测试证据保存在本地requirements/validation，不是完整语义验收或质量冻结。

当前全部173个授权要求视图已按同一源码重建，来源传输完整性失败为0，semantic_complete仍为false；实际源码身份、视图摘要及受控回归由唯一报告的data/diagnosis-summary.json和本地requirements/current/index.json维护。validation/actual-source-diagnosis.json记录已承接的Huawei L1818父绑定及Alibaba L114/L2353未解正文；不把来源完整当作语义完整。TOC来源adapter只核对原有标题、父路径、表格轴和实际关系，普通标题不能借导航schema豁免；未知格位及截断HTML保留原字并隔离，不从原件补结构。

原始ATX标题须独立传到正文与具体表格格位，每个业务owner的scope及对应绑定都要成立，不能用另一条正文membership抵消冲突。Name等原子字段不能屏蔽分号或换行后的未标签叙事；有限后置介词短语无作用域关系时继续pending，不扩大语法或把整段object回显当作解释。五个input_scope_context只能承接原authorization_dependency；host与导出均须与manifest的完整Lite声明核对，不能从缩小的保存case集合重新定义范围。

全范围diagnostic与正式评分使用相同的当前冻结和独立结构绑定；显式列出全部ID也不能绕过。没有冻结时只允许显式严格子集的软件诊断，不发布成绩；当前继续先做source-only要求重建，不启动真实候选回放。

年度枚举引言已接实际列表边界、共享年度、省略主体和成员关系；财表分类父链已接原单位及币种作用域。实际Huawei L1456只解决引言角色与15项列表的范围，成员业务仍有未解；L1810/L1815小计已绑定各自分类与L1792单位，L1818归属声明现可通过实际父绑定关联三组子项的六个年度事实。这是expected要求读取和审计修复，没有候选输出改善或完整样本验收结论。代码与测试提交均不是原任务完成，软件缺口应在既有授权内继续推进，不能等待五个保留范围的答复才做其余工作。

共享最终等价规则必须实际参与B身份/完整记录及L端点判对，不能只模糊召回再按原字符串拒绝。支持有依据的表示、句式、业务标签和受控错字等价；数值不参与位置选择，主体、范围、期间、保护词和冲突检查保留完整轨迹。用户已明确允许同量纲同币种下的无损精确数量换算；T原字不变，不做汇率、舍入容差或缺值推算，也不授权服务改写原数值。

八组均比较自己的原生到实际最终交付。只有P07/P08保留真实baseline/current配对，P01-P06不制造历史baseline。适配按Docling、Paddle、GLM、DocVortex及ContentBlock实际格式保全原文、格位、头链、引用、顺序、媒体和失败；不重新converter或模型推理，不从审计raw或另一管线择优补答案。新增执行保留实际阶段与编辑账本，缺失历史阶段不得冒充已保存。

service_stages现有对象账本使用实际审计JSON pointer及摘要，按声明来源配对和精确来源分区记录变化，原文字edits保留。无法证明的来源、对应、渲染及原因保持unknown/unmatched/unrecorded，producer原因只在原编辑精确回放后引用。它尚未建立逐要求八类增损归因，也未通过真实八组交付验收；不得把审计对象仍存在当作最终文字或资产已经保全。

候选CPU回放保持8CPU、8GiB、外层串行、无网络、无GPU和NoInference硬拒绝；expected永不挂载。来源许可必须按实际页分支传递，视觉分支不得借PDF字层或矢量格补答案。每组使用已有预热、173个质量样本和固定80页三次性能重复；原生推理及原测量不重跑，费用不相加冒充新端到端实测。不得操作GPU/TTS/在线服务、部署、Full或额外PDF。

五个跨页样本保留全部目标和范围待确认状态，不能自动裁段或解除范围阻塞；其它软件工作继续推进。软件其它语义门槛未通过时，增加pending、测试通过和遍历完成也不能宣称任务完成。代码或规则改变后删除失效评分派生物，不归档或继承旧成绩；有效native、实际正文、资产和原始观测保留。

最终冻结一套要求模型、读取器、等价规则和评分依赖，用16CPU进程统一评分全部受影响组。轨迹通过共享不可变来源引用与流式写入/汇总保留，不能裁剪命中或排除理由。报告分别维护八组原生、八组最终及增损、P07/P08历史配对，质量三层各占1/3、成本另列。只维护benchmark/reports/lite/report.md及相邻附录和数据；五个范围未确认前不发布完整质量成绩。通用检查永久排除语料、datasets、reference-decisions、runs及reports。
