# MO-Parse 数据集与解析评测标准

本文件维护数据集范围、评分与计时。用户于2026-10-24批准制作 `moparse-dataset-v1-lite`、`moparse-dataset-v1-full`，建立新工具并执行Lite对照。[待测试管线](pipelines-to-test.md)维护八组配置，[MinerU调优](mineru-tuning.md)仅维护内部参数实验。本文是协议，不是完成声明；实际制作、视觉确认和测量状态以人工记录及新运行报告为准。

## 1. 自动评分与语料审查

[永久规则](../AGENTS.md#highest-priority-permanent-corpus-rule)继续禁止机械复核语料：原件、expected、标注、映射及资产的真实性、分类、审核状态必须来自实际打开原页后的视觉对照，不能通过计数、哈希、格式、链接、文字层、OCR或解析器结果建立；不得自动生成、修复或改写参考。

用户明确允许独立的自动评分：对照冻结且已目视确认的参考计算被测管线成绩。评分只读参考，不提供语料检查或修复命令，不把模型成绩当语料验收。参考疑问保持待确认，回看原页；不能直接按差异修改expected。参考经视觉修订后记录证据，并重评全部受影响配置。

包装工具只按人工清单复制文件或提取PDF指定页面，不选页、不解释内容、不推断映射、不生成正确或通过结论。通用检查永久排除语料、datasets及benchmark/reports，显式路径调用亦排除。

评价对象是管线原生结果、忠实研究Markdown及必要资产，不是MO-Parse最终格式。保留GFM/HTML表格、页眉页脚不算解析格式错误。表格语义转换、布局正文整理、服务清理和接口交付属于[最终契约](../docs/specs/moparse-output-spec.md)的独立工程工作，不混入本轮质量或耗时。

## 2. 数据集、选样与视觉标注

| 数据集 | 范围 | 输入及参考 |
| --- | --- | --- |
| moparse-dataset-v1-lite | 800个实际输入页 | 单页、连续页段或完整短文档，现有参考冻结副本及人工评分索引 |
| moparse-dataset-v1-full | 全部现有expected对应原件 | 完整PDF、参考、图片及真实审核记录；本轮不启动Full推理 |

现有作者说明记载113份、7,070页，不是本轮机械计数或新的全文验收。Full保留历史审核状态和未知，不因包装升级Gold，不自动纳入没有expected的原件。本轮优先补齐Lite评分标注，Full剩余标注留待后续。

两套包各自包含实际PDF、参考、图片、清单、评分索引和使用说明，运行所需路径均在包内。Lite携带相关expected全文，人工索引引用范围；不自动截断跨页段落、共享表头或生成第二份正文。打包不授权公开发布或重新许可。

### 2.1 分类与输入范围

在查看待测输出前视觉分类和选页。标签可并存：原生/扫描/混合/不确定，正文/多栏/数据表/网格正文/混合区域/图片，多层表头/合并格/跨页/方向/低可辨性，以及语言、文档类型、家族、原件长度和开发暴露。现有标签只供导航，不能替代视觉判断。

兼顾普通内容与真实难点，不机械均分配额。单页可独立入选，一个长文档可提供多个独立连续页段；不拼接不相邻页面、不重复来源页占用800页。保留原文字层、矢量、图像及方向，不统一栅格化。

每个样本独立运行，人工记录原文档、物理页与本地输入页对应。未提供的前页标题、表头或限定不作为必答；跨页任务包含必要上下文。Lite结论不推广为完整长文档稳定性。80页性能子集由Lite完整样本组成，8页预检和预热集亦来自Lite，均标记开发暴露。Lite与Full共同来源及同模板家族不能宣称独立未见。

额外六份公开PDF继续暂不处理；Office、视频、手写及新来源不因本任务自动纳入。

### 2.2 评分索引

每个声称确认的页必须实际打开阅读并对照当前expected，记录原件、物理页、输入页、参考范围、评价单元、可辨状态、复核者及来源判断。未读、不可辨或缺上下文的内容保持pending、unknown或out_of_scope。

正文覆盖完整段落、标题和列表；表格覆盖完整选定表或上下文充分的表段。完整表行可记table_record，保留其完整语义参考；原始单格记table_cell，只有视觉标注支持的格位、跨度才评分。关键字段需明确行列标题、单位、期间和附注，不能从语义条目反推原始网格。网格正文评价文字与读序。图片只评价源图、图题和原位引用，不建立图意、节点、边或趋势标注。

expected按列书写而原页按行组织时，一个table_record可用reference.fragments列出人工确认的多个原文范围；这些范围只供引用导航，完整行仍是一个评价单元，不能重复认领同一原生行。不得从碎片自动生成字段或关系。源表明确的空格用value_status=blank及空值标注，只有原生明确提供空格时才算空白正确；缺失格与空白格分开，空值不进入字符分母。

索引保存引用和评价说明，不是第二份全文。既有来源映射仅供导航。scoring.exhaustive_units、scoring.exhaustive_output_scope及scoring.exhaustive_relations默认false；只有实际穷尽标注的范围才true。存在性precision还需明确完整业务目标与合法页面家具的闭合范围，单有完整正文标注不够；页面家具只能按预先目视确认的完整原文项目排除，不能按数字子串或管线自行命名排除。非穷尽范围的precision/F1记NA，报告目标recall及覆盖，不能把其余合法输出当幻觉。

expected的Markdown显示标记只作语法投影，不进入源文字字符分母。作者添加的冒号、字段连接词、空白说明及重组语句不能被自动删去或当作原文字面；此类单元明确text_comparison=not_applicable。需要评价其存在或关系时，使用人工从原页确认的短localization_literal；没有该来源定位参考时记评分覆盖不足，相关关系不算模型遗漏。table_record继续按独立标注字段评价，不计算整行语义条目编辑距离。

已确认图片目标继续列入覆盖记录，但参考资产名不要求候选复现。没有独立输出身份对应时，图片保全保持未测，不因不同文件名、无图内文字或无法自动定位判丢图。自动图像引用指标只描述能定位的子范围，不能替代完整图片目标的视觉保全评价；原图题和图外文字另作正文目标。

KPI卡片的标签可用localization_scope=label_only作定位锚点，不能由找到标签推定整张卡片文字或数值正确。目视确认的标签和值分别标注，来源已知的字段关系始终保留目标分母；原生输出能否表达该关系属于预测可观测性。共享页面或一般容器本身不证明数值归属，需原生明确关系或实际同一文字项的标签分隔符证据。来源没有行标题的表格小计保持来源归属未知，不补造“合计”标题。

## 3. 原生读取

每组字段及媒体见[输出与适配](../docs/pipelines/README.md)。同族可共享无损读取函数，配置身份、版本、分支、页序、失败及原生产物分别保留。执行器与适配器不能访问expected；只读已有文本、阅读顺序、层级、格位、跨度、明确关系、媒体和状态，不补答案、不引入其他解析器、不按参考重排。

保存完整原生对象或回包、忠实Markdown、实际图片及原生字段位置。原生已有信息被读取丢失，先修读取；原生未提供、入口未暴露、适配错误与解析失败分开。畸形局部不得吞掉有效邻居。共享评分记录不是候选必须实现的语义接口，不取代原生结构。

明确的HTML或GFM表格语法提供原始格位和表头显示角色，读取这些已有结构不证明业务表头关系。网格内正文仍可在原生文字范围内取得内容成绩，字段绑定与数据表语义另评。原生children、parent、caption、footnote引用及实际声明的标题级别可以提供关系证据；纯标签、坐标相邻或同页不能自动生成层级或图文对应。标题作用范围沿实际原生顺序和级别读取，不按参考修正。

SDK自身的逐块忠实Markdown导出若明确给出标题语法，可以作为该原生块的标题级别证据，同时保留原始文字字段和导出字段引用；不能由评测器根据标题样子或参考层级自行添加井号。导出中的文字规范化不替换原文字段的严格字符评分。

## 4. 指标与匹配

| 维度 | 比较对象 | 成绩与分母 |
| --- | --- | --- |
| 存在性 | 已确认完整评价单元 | 检出、遗漏、重复和额外输出；依穷尽声明报告P/R/F1 |
| 文字 | 已确认正文或表格字符 | 严格CER、归一化编辑相似度及排版等价诊断，正文/表格分报 |
| 关系 | 先后、标题从属、图文对应等 | 显式关系P/R/F1、端点覆盖，不展开所有传递边重复计分 |
| 表格归属 | 值及完整行列标题、单位、期间、附注 | 严格字段关系正确性和召回，关键数值单列 |
| 结构 | 独立标注的行列、跨度、相对关系 | 原生能力、正确性和覆盖，无标注时NA |
| 跨页 | 内容与应连接/应分开关系 | 正确、错误、遗漏；完整物理片段与错误合并分开 |
| 图片 | 标注图片、图题及引用 | 资产与引用覆盖、对应；图像内容保全不能凭数量或哈希证明 |
| 稳定性 | 全部正式输入及已确认目标 | 完成、部分、失败、超时、资源不足、未知、未评 |

CER=(替换数+删除数+插入数)/参考字符数，允许大于1。编辑相似度=1-编辑距离/max(参考长度,输出长度)。有参考无输出计删除；两侧均空不进入字符分母，空白处理单列。相似度不证明数值、符号、单位、期间或归属正确，关键项另报严格成绩。

已确认目标遗漏、未提供或运行失败时留在目标覆盖分母。不可辨、未标注、参考待确认、评分歧义分开，不填正确或零错误；缺测不补零，失败耗时不是零成本。

### 4.1 定位

先定位后评价，优先使用样本及原生已有页范围，兼容一个段落对应多块。精确匹配优先，归一化相似度0.8只作定位门槛。短标签、纯数字、重复值需已定位的父段或表格范围，不能全文找到同值即通过。相同输出字符范围不能重复满足独立目标。

匹配不能使用待评价顺序或字段归属奖励正确关系。定位后按原文及原生位置计分，不补字、不改值、不重排。无法唯一定位时保存候选及原因，保持待判，不选最有利对应。已定位内容内的遗漏、插入依编辑距离计分；未认领的额外输出在闭合范围的存在性precision中单列，不能未经内容归属直接加入某段正文CER。未标合法内容不能自动当FP。

正文同时报告两种明确区分的字符口径：text保留所有已知目标，未唯一定位的参考暂作删除，给出保守的目标成绩；text_aligned只对已唯一定位单元计算条件字符准确度，必须同时给出已对齐单元和参考字符覆盖。前者不声称每段未定位文字确被解析器漏掉，后者不能冒充全目标准确率。纯数字及关键字段不因相似度高而算正确；表格字段另报目标正确率、已观测条件准确率和字段定位覆盖。

容错定位先求最小Levenshtein距离的原生子串，再按1-距离/max长度应用0.8门槛；并列候选保持歧义。相邻原生文本块可形成带原始字符范围的定位视图，图片和原生容器边界中断该视图，不产生额外输出单元；同一网格内正文按实际原生格序读取，不以此补造业务行列关系。表头标签可定位在原生同格的完整文字边界内，例如2024与$m共享一格；不得在万元中匹配元，也不得以待评数值或关系决定表头候选。

页面家具与业务范围由预先视觉标注确定，不能让方法自称footer排除业务遗漏。匹配先用受控样例固定，不根据正式成绩调门槛。评分器缺陷修复后重评全部受影响产物并保留版本记录，不根据某组答案修改Gold。

先后关系另给预声明端点对的方向分类P/R/F1：正确方向计TP，原生顺序相反计FP及FN，端点无法定位仅记FN及定位覆盖；该口径只覆盖这些端点对，不声称穷尽文档所有阅读边。一般显式关系没有穷尽标注时仍保持全局precision为NA；可单列实际穷尽子范围的precision及其覆盖，不能把局部precision冒充全量。跨页表连接可使用原生同一表容器身份，分开关系使用两个独立原生表容器，不从相似标签推断续表。

### 4.2 表示与汇总

沿用mo-parse-eval-text-v1：排版等价诊断仅将U+FF01至U+FF5E映射为ASCII、U+3000映射为空格，不用NFKC、不删标点、不修数字。连续排版空白在定位和排版等价诊断中折叠为一个ASCII空格；严格字符成绩仍保留语法投影后的实际字符与空白。关键字段符号保留。Markdown/HTML按实际语法读取，不以源码装饰判文字错误。

原生字段须声明plain、markdown或html，不能通过星号或文字外观猜测格式。严格字符成绩指语法投影后的可见文字，并保留原生字段、字符范围和投影身份。只有真实HTML或SDK明确的上标格式证据才允许把已标注的数值和脚注标记分开比较；纯文本150.14不能按参考期望变成150.1加脚注4。原生跨页对象可声明完整provenance_pages，不能据此替每个单元捏造精确物理页。定位流和先后评价使用实际native_sequence，不按物理页重新修正原生阅读顺序。

正文按正文单元，表格按内容、字段关系及独立结构比较，不能将整篇语义列表与去标签HTML全文算一个距离。原生格位跨度可支持对应评分，不能借Gold补预测路径。没有来源结构标注时记覆盖不足。

table_records.grid_relation只表示已独立定位表头后，原生格位是否给出唯一的交叉值位置，是字段定位诊断；它不是原始结构准确率。原始结构成绩由具有独立格位和跨度标注的table_grid给出。字段字面正确性、关系正确性及定位覆盖分别保留。

按样本、原文档、家族和类别报告宏平均及内容量加权结果，保留逐项分母。不同单位、重叠任务与重复运行不合成总准确率或独立样本数；首轮无任意加权冠军，不据最好成绩倒推采用门槛。

## 5. 运行和计时

各组使用同一冻结输入和顺序。Lite输入为已声明单页/页段PDF，Full为完整原件；人工标签只分层，不免费路由。共同前处理、缓存及来源权限见[固定配置](pipelines-to-test.md)。

worker获得执行权且输入就绪后以单调时钟从开始处理量到原生解析、忠实Markdown及必要资产内容就绪。包含读取、方向与来源判断、渲染、路由、推理、必要切换和导出。纯视觉不能从缓存图开始。公开API传输、排队、轮询、下载、纯持久化、评分和服务转换另计；必要裁图、渲染、编码计入解析。

不把重叠阶段求和，不用HTTP总时长减常数，不复制或相减现有duration_ms修补边界。GPU 1单张RTX 2080 Ti、200 W、总显存20 GiB；解析前处理8 CPU/8 GiB宿主内存，GPU服务合计4 CPU/20 GiB宿主内存；记录quota与affinity。外层并发1，后端请求上限4，混合后端共享预算。支持CUDA Graphs时在预算内开启，以真实捕获推理核实，例外留原因和恢复条件；torch.compile独立记录。

初始化、加载和共同8页预热单列。每组800页一次，标n=1；80页另测三轮，报告各轮、中位数、最小最大及波动，不能冒充800页三轮。平均每页处理成本不能称逐页延迟。

预检后冻结共同样本截止min(3600,max(300,3×最慢成功预检页耗时×输入页数))秒。未成功预检先排准备故障，不把未实现入口当模型失败。正式失败、超时、超预算保留，不静默换配置或重跑。收到响应或执行未知不重试；取消保持所有权直到原请求返回或远端确认清理。

## 6. 维护窗口与报告

先记录原状态并排空请求，正式窗口临时停GPU 1上的MO-Parse模型服务和qwen3-tts-openai.service。GPU 0及其他项目不动。隔离实验按P01至P08执行，正常、错误、取消均清理并恢复原服务原配置，核实恢复结果。

新报告放benchmark/reports，原生及评分细节放artifacts，不进通用检查或线上镜像。报告包括范围、分类、未知、暴露、实际模型软件、资源、覆盖、质量、800页n=1、80页三轮、初始化预热、失败及原生定位；机器明细、汇总、Markdown可从冻结产物重生。不得引用旧成绩、称自动评分为语料验收或称Lite为Full结论。

入口为python -m moparse_eval package|run|score|report。正式推理必须等800页参考实际确认并冻结，不以程序计数或文件存在宣布可跑。当前状态以人工进度与真实产物为准，不预填成功。
