# 原生正文与表格转换入口诊断

2026-10-28核对实际调用路径，完成原生正文、来源结构及局部关系入口修复，并用人工编写的内存结构和合成PDF验证。本文件只记录软件机制；实际工程触发及质量由[评测索引](../reports/README.md)链接的新服务报告维护。软件回归不访问语料或参考；真实输入只由授权候选worker正常处理，不形成语料复核结论。

## 原生文字有两条不同的数据路径

八管线原生执行与MO-Parse服务转换是不同的测量对象。[研究执行器](../../moparse_eval/executors.py)中P01/P02使用PDFium原生后端且关闭OCR，P06/P07使用MinerU的TXT模式；P08按声明只接收渲染图。它们没有调用MO-Parse表格语义转换。不能用服务中的未调用函数证明原生配置没有使用文字层。

修复前，[PageEvidence](../../app/services/evidence_service.py)读取原生文字，[DocumentIRService](../../app/services/ir_service.py)把原生块写入IR，文档及页面renderings却继续采用解析器Markdown。新增[NativeTextService](../../app/services/native_text_service.py)在来源处理后、最终导出前选择唯一拥有的同区原生正文，保留已知标题、列表和引用；有明确同栏顺序锚点时可恢复遗漏段落。原候选、源文字和冲突保留在诊断中，表、图、未知区域与页面家具不展开为普通正文。

`native_markdown()`继续不是全文替换入口：其简单栏位和字体式标题判断不能替代区域归属。新服务对重复显示片段、复杂行内格式、重叠来源、乱码及扫描或混合页保留原候选；没有可信顺序锚点的空白候选也不强制展开所有原生文字。它修复的是来源已知区域的正文交接，不宣称完整阅读顺序能力。

## 表格转换有两道独立入口

[PDFTableEvidenceService](../../app/services/pdf_table_evidence_service.py)已去掉仅处理MinerU的过滤。矢量途径按实际相交线段裁取ROI，支持矩形描边，不再因整个绘图对象超界而丢掉有效线段；另有明确单元格分区与源字形绑定途径。两者都不修改原值，结构与语义用途分别判断；新分区入口不扩张跨页续接授权。

绑定完成后，`_header_candidates()`可根据完整源跨度、期间与字段文字、数值记录和样式对比支持多层或左对齐表头；纯数字年份不再一概排除。行分组需要源合并范围，序号列与名称主体分开。短字段使用独立`field_scopes`；没有关系证据的网格正文不因底纹或相邻而转换。

[TableSemanticsService](../../app/services/table_semantics_service.py)按完整安全源行及跨度组件处理局部关系。partial视图按原行顺序交错确定记录与剩余GFM，不把完整原表再与语义条目叠加。剩余行给出精确显示映射供最终读取；一个区域未解决不再抹去不依赖它的记录。完整转换、部分转换和保全分别统计，仍不能由第一道修复数量预报最终质量增幅。

## 受控复现

[纯内存探针](service-entrypoints-probe.py)不接收语料参数，不读PDF或参考，不初始化模型；IR中的来源字节记账被显式替换为固定合成值。

| 合成结构 | 修复后的实际行为 |
| --- | --- |
| 同区原生段落与唯一解析器正文存在单字识别差异 | 原生文字参与最终导出，并保存原候选与来源 |
| 表头为`Metric / 2024 / 2023`，其他关联条件满足 | 产生一个完整表头scope |
| 期间标题为`Current / Prior` | 产生一个scope |
| 同一明确期间表头改为左对齐 | 仍产生scope |
| 数值含年份片段，如`20240`、`2024.50`、`-2024` | 不提供期间证据，不因此成为表头 |
| 一个可转换记录后增加行主体未解决的记录 | 变为partial，确定记录保留，未解决原行另保全 |

运行命令如下，输出只说明软件对合成输入的行为，不评价任何真实页面内容。

```bash
PYTHONPATH=. .venv/bin/python benchmark/diagnostics/service-entrypoints-probe.py
```

## 处理决定

现有八组原生数值没有因这两个MO-Parse入口而失效。修复前服务运行保留其冻结身份；新运行另外保存六个候选阶段，阶段快照显示读取和评分在主计时外，候选抓取CPU开销留在主计时内并单列。阶段变化只描述同一流水线顺序，不冒充独立消融。

新实现使用独立冻结的软件身份，复用P07原生产物重新执行服务质量集及性能子集，并用相同标准评分；无需为此重做八组GPU推理。新增独立原生PDF方法或改变底层解析配置时，再冻结及实测该配置。来源、语义和原生正文CPU阶段在重复取消后仍等待原worker退出，不自动重试已收到的错误。

期间证据的合成负例曾发现年份子串及记录行边界缺陷；修复后金额、负号、百分比和长编号不再借四位片段充当期间，已有表头后的年份数值记录也不因居中而变成内部换头。受影响的未评分执行已撤回清理，仅保留[软件诊断](service-period-boundary.json)，不保存质量成绩或撤回候选作为基线。

独立合成复现还发现原生正文的区域保全缺陷：先过滤不健康或受保护的原生块，再用剩余子集替换整个解析器正文框，会隐式删除该框中的其他内容。现已要求整框具备完整、健康、唯一归属的来源覆盖，并同时保护图表、未知区域、页面家具的实际显示片段及几何范围；证据收集阶段排除的重复页边块也保留用于区域保护。未完整归属的区域保留原候选，不能用覆盖比例代替完整保全。受影响执行及不完整评分已清理，仅保留[软件诊断](native-region-boundary.json)和合成回归，不作为质量基线。

同位重复绘制也会让可读文字层产生重复正文。现按同一raw block内line/span的近同位origin及双向高度重合bbox记录叠印风险，不以重复子串判定；来源字节保持原样，有风险的来源不参与正文替换或插入。合成PDF覆盖同位及小偏移重绘、正常相邻和跨行重复、单span内合法重复，以及独立正常邻区继续处理。受影响候选和不完整评分已撤回清理，只保留[叠印机制诊断](native-source-overprint.json)。

PDF物理分块不能直接成为段落。已有parser单段中的源line/block边界现在只沿唯一支持的原段空白投影；英文同词字体分块不加词间空格，CJK软换行不加段落，无法唯一确认边界时保留原候选。真实原始块字面与实际替换字面分开保存。重建后若只差既定字宽及排版空白，保留已有parser格式并另记preserved，不把它算作修复动作；现有多段、列表及复杂格式仍先保全。

同样，语义尚未分类不等于真实网格几何不可读。精确、唯一显示且完全不与明确scope相交的残余网格保留原生行列跨度，不添加表头或字段路径；有真实scope冲突、缺失显示及跨界的关系仍未知。两项缺陷及独立合成复现见[段落与网格读取诊断](native-paragraph-and-grid-readback.json)。
