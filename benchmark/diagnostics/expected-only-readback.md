# expected唯一标准的程序读取修正

本记录只说明评分软件缺陷及受控验证，不提供语料验收、解析质量或耗时结论。当前验收口径由[评测任务](../evaluation-tasks.md#current-task-expected-only)维护，真实执行状态由[评测索引](../reports/README.md)维护。

旧入口直接消费评价索引的短字面与字段答案，并支持原图人工排除；服务配对还继承该排除。新入口只读canonical expected和现有选段声明，历史评价文件不提供答案。显式裁定参数在读取任何材料前拒绝，旧运行中的裁定字段不传入新评分。

expected与实际Markdown均按公开语法读取。读取器保留嵌套列表的父记录、多年度字段、明确分列说明、字段路径、完整段落及原文位置。转换正文的范围段、独立主体、分号和括号内限定分别处理，括号内分号不能切断下一字段；数学或会计括号不因外形相似被剥除。仅有名称和值的明确记录允许在候选唯一对应值上判分，多列值不能按期望值挑选。

单位可以印在行名、列表头或明确局部限定中；读取器分开保留单位与业务标签，不要求复制同一放置位置。脚注上标必须有候选自身的格式和关联注释支持；业务比较核对附注内容，字符诊断保留原始表示，无注释支持的指数不按脚注删掉。未知表头不被制造成必答表头。

八组运行的完整样本范围、目标身份及分母须一致。合成运行覆盖所有八组及P07/P08修改前后正文；相同输出更换管线ID必须得到相同判分与证据。最终正文只从保存Markdown读取，不利用私有IR重建答案。缺失候选判错，读取故障阻止发布；评分产物不可改写被测原生产物、执行计时或参考。

工程回归位于`tests/unit/test_expected_only_evaluation.py`及`tests/unit/test_expected_evaluation_run.py`，并结合既有字段、上下文、原生读回、评分入口及冻结测试执行。报告重生只读取已完成的评分产物，可在参考和数据集目录离线时执行；混合软件身份或目标范围不一致时拒绝发布。

长Unicode段落的HW编辑距离定位在参考字母表超过Edlib限制时采用NumPy逐行前缀最小值计算；它与标量动态规划保留相同成本、起止位置和对角线、上方、左方的平局顺序。穷举短文本、随机Unicode、超过255种字符及阈值反例覆盖两种实现的一致性，依赖版本进入软件身份。显式年度元组读取并列子标题，证券代码等具名列表仍作为列表值，不虚构子列。真实重评遇到的软件故障保留失败运行，不发布未完成索引，也不将其算为候选错误。

真实输出诊断补齐了多表位置、空字段、具名类别、句末标点与转置单位读取。Markdown或HTML表格的单元格ID包含其实际行位置，不能由读取器制造跨表ID冲突。明确“原表留空”与实际存在的空字段比较，缺少字段或候选不能代替空值。币种与金额单位分开读取，股份等明确局部数量单位优先。重复业务标签在不同声明标题中出现时，范围先参与定位，不能按数值选择线上或线下记录。

字符规范化、标签及路径缓存只缓存纯函数计算；局部表头缓存只在一次候选评分内有效。分析可并行执行，合成回归要求串行与并行得到相同逐项判定及证据。输出运行目录不可覆盖，不能把评分产物写入只读expected或数据包。资产交付只读取候选自己的清单、文件与Markdown引用，不打开图片内容，不给正文补分。

范围元数据的句末冒号不构成下一层字段名；同条记录的空字段仍是显式空值。具名父项保留名称和值两层范围，正文自己的复合主体也独立提供该具名断言。原生正文的业务定位只使用明示主体、具名身份和范围，不再把金额、附注或其他普通字段值当成可替代的业务名称。合成反例覆盖范围句末冒号与空字段的组合、父项值替换、无关附注借名称以及缺少原生配对时禁止虚构错误阶段。

同一完整表题可以写在明确的范围路径中，也可以拆成紧邻表格的编号、年度标题和期末说明。共同读取器保留所有文字及编号，只消除明示路径分隔和中文标签排版空白；分段图题必须有编号锚点，不能跨过另一表格、图片或无关正文。受控反例覆盖错误表号、错误年度、错误业务名称和邻表范围隔离，防止偏向后处理新排版。

编号表题在expected中明确规定所属表格，即使某个指标只出现一次，也不能从另一编号表中借取同名指标。父路径不同的同名末级指标同样需要保留表格范围；范围先参与候选定位，数值不能决定取哪个表。受控测试分别检查唯一指标的表号交换、不同父分组下的同名指标、跨表值交换以及原正确项退化。
