# MO-Parse：保存 Native 的首版质量研究结论

2026-11-18。研究对象是 S1–S9 × P01–P08 的固定开发暴露选段。接手 HEAD 为 `21455264a76fac91f3e79d11c40cd8c3dd858b82`，接手时工作区干净；没有回退、提交或推送。本报告保留[既有结果报告](native-limited-research-results.md)，不重写历史成绩，不形成完整 Lite 或文档类型总体排名。

第一版结论是：S1/P06 与 P07 的全部 B 差距来自一处已证实并修复的评测投影缺陷；S7 的零 B 主要由共同标题归属条件放大，不能解释为正文全失；S5 的低分被表格字段读取和展开表达的比较方式主导，但同时存在可定位的真实日期错误；S4 七组相同的 L 来自同一组列表父链要求，不表示七种 Native 结构相同。确实有原生文本缺失的对象，例如 S4/P05 的两段定义，必须与这些共同扣分分开处理。

## 证据、身份与贡献口径

原始比较使用[原 r7 执行索引][old-index]及其 72 份完整 trace，软件 ID 为 `a6cabfbf336372fa40ce9eca26da167d9817617b8c4cb4e699b2bc363069a990`。本轮使用 `moparse_eval.trace_storage.read_score` 展开存储引用，读取绑定的 Expected 文字、两侧 AST、实际对应、扣分分项及保存 Native 的文字和结构；没有把旧 Markdown 摘要作为判定证据。全部 72 份分数及本报告引用的关键原生对象均可访问。完整 Native 原始文件由[输入绑定][inputs]定位，`#/…` 是该文件内的 locator，表格 `::html/cell[n]` 是读取 trace 保留的原始 HTML 单元格位置。

新增的[代表性证据摘录][examples]包含 selection、pipeline、原分数 SHA、`outcome_index`、要求及其原文来源、候选对象、已选对应和原始 locator；完整竞争对应仍引用原 trace，没有复制整套工件。[失分贡献明细][loss]归并四组选段全部 32 个组合的责任及扣分分项，不生成替代成绩。[实际 producer 与逐页分支摘录][routes]回指原输入绑定，配置全文仍在原绑定中。

producer 名称来自原执行绑定，Native 没有独立的顶层同名字段。本轮逐份回读 72 组原 Native 和 observation，核对其原 SHA、pipeline、`config`、执行身份及逐页分支均与绑定一致；实际后端归因按逐页 branch，不按配置名称猜测。该检查只读取保存的 JSON 元数据，没有另建 Preflight 或采用门禁。

以下“项贡献”均以原要求的一票为单位，除以该层原分母再乘 100 才是分数点。一个标题或字段轴可以影响许多要求，要求数不当作独立错误数。L 按原要求内各分项权重分摊失分；B 的正文先统计保护词及编辑导致的损失，再统计归属门槛抹去的剩余内容贡献，互不重复。后者只是扣分机制分解，不是放宽归属后可发布的业务分数，更不证明对应正文的完整语义已经正确。

计分定义仍为[连续 AST 合同](../../evaluation-tasks.md#固定native研究的连续计分2026-11-17授权)：B 普通正文只衡量有界内容保留；字段使用自己的主体、轴、期间、币种和范围定位，再比较值。没有调整阈值、拆合上限、权重、分母或匹配算法。类型化字段的“无对应”与真实缺失分开，不能据前者宣布 Native 无此信息。

原因标记为 A 原生内容缺失或错误、B 原生结构或关系组织不足、C 可证的读取/投影/计分实现误判、D 当前定义的表达敏感性或能力边界、E 证据不足。一个责任可以同时暴露几类问题；没有唯一证据时不强行拆成各类缺陷率。

源码只改动 [continuous_document.py](../../../moparse_eval/continuous_document.py) 的该片段提取机制，正反例在 [test_continuous_document.py](../../../tests/unit/test_continuous_document.py)；该模块的受控回归、两个修改文件的 Ruff 和差异检查通过。Markdown 政策检查按项目规则排除报告、运行工件及语料；没有为本次接手启动全量测试。这些软件检查不替代下述真实对象的影响验证。
