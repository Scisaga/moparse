# 原生正确信息保留的修复

问题集中在读取、关系绑定和验收门槛。现有IR已经能保存来源格、完整标题路径、单位、期间及附注；本轮修复沿用这些来源信息，使实际交付的Markdown保留正确内容。

| 根因 | 具体影响 | 修复 |
| --- | --- | --- |
| 把业务名词、计量单位和普通数字混用 | “库存股”被解释为股单位，年龄被打印成“52股”，不同业务标签还能因单位尾词而混淆 | 明确单位适用类型，区分完整单位声明与业务名词；相同事实的矛盾单位不能被另一条正确陈述掩盖 |
| 读取器对等价表达处理不同 | 合并单元格读空、多层列路径及复合主体无法定位，同一列表后续记录丢失币种 | 按实际字段、跨度、公开路径和语法作用域读取，完整业务标签先定位，再比较数值与限定 |
| 纯文本字段和表头的分类顺序错误 | 中间版本把“姓名｜主要工作经历”误作属性记录，导致下面记录失去列头 | 先识别完整表头，再生成属性记录；保留跨列表名，布局证据继续限制字段转换 |
| 普通文字只在单块内补查完整字面 | 完整标题拆成标题与段落后，文字尚在却判缺失 | 在实际相邻文本中对照完整字面，保存每个组成片段的位置；不跨表、图片或已知页范围，不跳过否定，不以文字邻接建立业务关系 |
| 采用只检查正文版本间的新增损失 | 原生到正文的旧问题持续存在时仍能通过 | 同时检查修改前后零损失，以及原生正确的全部内容目标在最终正文中零损失；业务字段单列，报告从逐项结果复算门槛 |

中间07版的表头回归由程序门槛发现，未采用。08版正文重新完成P07/P08各800页回放和固定80页三轮；后续仅修共同读取时保留实际处理计时，对八组原生及各正文版本统一重新评分。

所有质量判定来自只读canonical expected与实际保存输出的共同程序。诊断阅读只用于修复软件，未改变expected、标注或来源映射。具体业务收益、全部内容保留、剩余错误和成本以本目录当前报告及逐项产物为准。
