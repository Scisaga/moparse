# MinerU 调优计划

本文定义 MinerU 的独立调优起点、实验变量和验收方法，不包含历史成绩或耗时。完整解析管线的主对比组见[待测管线](pipelines-to-test.md)，数据集、标注及评分规则见[评测任务](evaluation-tasks.md)。这里的调优不增加或替代主对比组；文档编写本身不启动推理或部署。

调优在[研究顺序](../docs/research/research-framework.md#2-管线研究的顺序)中属于第 7 步的路线内参数研究，承接固定方法或有证据的选择策略，不要求先构建路由器。固定的是解析结果、忠实导出及质量口径，不是 MO-Parse 的接口最终格式；解析输出可保留表格和页面信息，服务语义转换不是本计划的前置条件或计时部分。本轮只调整文档，不启动推理、参数变更或部署。

## 框架、模型与执行路径

`MinerU 4.0.12` 是负责 PDF 分析、版面处理及结构组装的软件框架版本。视觉权重为 `opendatalab/MinerU2.5-Pro-2605-1.2B`，模型 revision 固定为 `08aaea840498d49ce16247b6263196cf02814885`；`mineru2.5-pro` 是 HTTP 模型服务的别名。这三个标识属于不同层次，不能根据框架版本推断模型版本，也不能通过修改服务别名宣称升级权重。

调优从当前代码的 `Advanced + TXT` 路径开始：CPU worker 负责原生 PDF 分析和小模型，视觉请求发往同一 revision 的本地 VLM 服务。`TXT` 表示使用 PDF 文字层参与解析，不代表关闭视觉模型。正式实验前记录实际软件包版本、代码提交、镜像摘要、模型 revision 和完整启动参数；源码中的配置值不是运行时验收证明。

先依据[管线输出与适配说明](../docs/pipelines/README.md)核对所调配置的原生产物、媒体与导出边界。当前 worker 的传输投影、原生 SDK 完整结果及 P06/P07 的混合组合不能互相冒充；调优只在固定的完整解析出口比较，不包含 MO-Parse 服务适配、转换和组装。

下表根据仓库的 `docker-compose.yml`、`native_worker/server.py` 和运行配方整理，作为待测起点，不表示已证明最优。MinerU 管线已移除独立 Docling 表头与来源冲突复核，调优不额外调用第二个解析器。输入从外部项目交接并明确纳入范围的冻结语料中选择，不在本项目重复生成语料或金标；`pdf_sample_extra/` 暂不处理。

部署代码起点与正式对比资源预算分别说明。调优实验沿用主对比的 8 CPU、8 GiB 解析 worker，以及 4 CPU、20 GiB GPU 推理侧宿主内存预算，使用同型号单 GPU、200 W 功率上限；受测显存16 GiB和TTS保持运行、评测期间不调用的条件以[评测标准](evaluation-tasks.md)为准。混合管线中的模型合计占用同一预算，不为 Docling、SDK 或第二个视觉模型额外增加资源。实际显存分配、模型共驻或串行装载方式在新实验前固定，不把线上多服务或双卡部署布局当作主对比资源条件。

本轮研究执行修复和工程预检不构成MinerU参数调优结果，也不授权启动新调优任务。主比较的当前运行状态与结果只由[评测索引](reports/README.md)维护，本文继续只维护独立调优方法，不恢复已撤销的旧成绩。

## CUDA Graphs 的默认要求

支持 CUDA Graphs 的 GPU 后端必须启用。`mode=0` 关闭的是 `torch.compile` 编译路径，`FULL_DECODE_ONLY` 配置的是 CUDA Graphs，两者必须分别解释和记录。正常配置不使用 `--enforce-eager`；只有明确命名的 eager 对照，或已有图捕获失败、显存预算超限、输出回归证据时，才允许关闭图，并记录恢复启用的条件。

正式测量前进行小规模真实捕获和推理试验，分别保存启动参数、捕获成功信息及请求期间的实际 `FULL` 回放记录。`/ready` 成功、存在捕获参数或看到启动时捕获完成，都不能替代请求期间的回放证明。记录缺失时将该证明标为缺测，不把参数开启当成实际执行结论。

图捕获占用计入模型服务的总显存预算。当前捕获尺寸固定为 `[1, 2, 3, 4]`，不为追求更大批次越过已分配的 CPU、宿主内存或显存资源。任何图开关对比都从同一 revision 和相同有效输入重新实测，不能根据其他实验耗时推算加速。

## 单因素调优顺序

先从[评测任务](evaluation-tasks.md)选取覆盖代表性工作量的固定子集，为原件字节、页范围、请求参数和输出阶段生成清单。所有候选读取完全相同的原 PDF，保留 PDF 入口，不用事先渲染的图片替代后宣称 PDF 吞吐提高。子集应覆盖文字层利用、密集表格、复杂跨度和较高峰值内存等实际成本，选定后不能按候选结果更换页面。

每个设置单独预热，预热内容、次数和耗时独立记录，然后至少执行 3 次完整测量。固定模型、输入、生成限制、缓存策略、硬件、功率、服务并发背景及计时边界；采用交错或轮换顺序减少固定执行顺序的影响，保留每次原始值。初始化、图捕获和预热成本单独记录，不计为零，也不混入热态组件耗时。

| 实验 | 改变的唯一因素 | 候选设置 | 其他条件 |
| --- | --- | --- | --- |
| 客户端并发 | 原生客户端发往 VLM 的并发数 | 1、2、3、4 | vLLM `max_num_seqs=4`、图捕获尺寸 1 至 4、ORT intra 8 和 inter 1 固定 |
| 服务调度容量 | vLLM `max_num_seqs` | 1、2、3、4 | 客户端并发 4、图捕获尺寸 1 至 4、ORT intra 8 和 inter 1 固定，不混入外部任务的接口排队 |
| CPU 线程 | ORT intra_op | 1、2、4、8 | inter_op 1、worker 8 CPU、客户端并发 4、vLLM 上限 4 和图设置固定 |
| CUDA Graphs | 图回放开启或 eager 对照 | 当前 FULL_DECODE_ONLY 配置、显式 eager 对照 | `torch.compile` 均为 mode 0，其余模型、容量、线程及输入固定；两组各自预热并记录显存 |

这些实验分别回答客户端并发、服务容量、CPU 线程和图执行的收益，不能把同时提高客户端并发、vLLM 容量及捕获上限的联合变化归因给其中一个变量。选择候选后，再做一次受限的组合确认；该确认单独标识，不称为新的单因素实验。

## 计时、质量与内存验收

主性能指标为 worker 内部直接测量的解析 walltime：从开始读取已就绪完整 PDF，到原始解析、研究侧忠实 Markdown 及必要资产生成完成。包含 PDF 解码或渲染、版面分析、文字层、声明的模型计算、原生结构组装、忠实导出与必要资产；不包含 MO-Parse 的数据表语义转换、布局正文还原、页面家具清理或接口正文组装。所有参数候选采用相同解析边界，不使用预先生成的中间结果缩短其中一组。

计时入口仍须按本节准备；现有 native worker 的 `duration_ms` 从 MinerU 调用前开始，漏掉之前的页数和尺寸读取，也未覆盖完整混合配置。远程适配器的同名字段又包含 HTTP 与写入，不能直接当作本计划主耗时；详见[源码边界](../docs/engineering/architecture.md#现有调用与计时字段)。

HTTP 请求、接口排队、上传和传输、状态轮询、结果下载及结果持久化全部排除，不设置相应耗时指标，也不将模型 HTTP 请求区间视为 GPU 推理时间。按统一协议在 worker 内记录解析和资产生成等阶段；并行阶段的区间保留重叠关系，不能求和替代处理 walltime。MO-Parse 的真实 HTTP 与最终格式验收另属服务工作，不计入解析性能，也不是参数比较必须先完成的步骤。

每个设置报告 3 次原始耗时、中位数、均值及范围，冷启动和预热另列。性能变化同时给出减少的秒数和同边界的相对变化；只有同源、同出口、同评分协议时，才讨论新增通过检查所需时间。检查项的重要性和覆盖不同，不把每秒通过项数称为全文准确率，也不把质量较差的快速输出直接判为更优。

按照[评测任务](evaluation-tasks.md)逐项检查正文保全与顺序、数字及符号、单位和期间、完整表头作用域、网格与跨度、来源绑定和原件证据保留。保留严格字符诊断与明确版本的宽度政策，各用各的分母；未知、未标注、失败和缺测分别报告。不能用文字命中或样式相似代替正确的列义及跨页关系。不要求解析结果满足多层语义列表、无表格或无页面家具；这些是 MO-Parse 服务转换要求，另行测试和计时。调优结论只能描述相同解析边界内的变化，不能宣称服务最终目标已完成。

同时采样 CPU worker 与 VLM 容器的 CPU、宿主内存、cgroup 峰值、OOM 事件及 GPU 进程自身显存。worker 在既定 8 GiB 内完成且不发生 OOM；长文档应检查各窗口后的内存是否持续增长，取消和超时后是否释放本次任务资源。VLM 模型、KV cache、CUDA Graphs 和工作区共同受实际显存约束，不能只按 KV 预算判断安全。

资源读数注明是整个实验单元还是测量轮次内的采样。按进程归属的模型显存与整卡显存分别报告；共享整卡功率、利用率和积分能耗包含其他工作，不作为解析器独占能耗。采样失败保留缺口，不补零。重复次数不足、资源超限、图回放无法证明或质量回归的候选不能直接替换起点。

## 实验交付要求

运行前确认实验范围、资源配额、输入清单、计时边界和评分协议已固定；运行时保存可复核的请求、有效配置、原始输出、逐轮处理测量与资源记录，并与当次代码和镜像身份绑定。本文只维护调优方法和配置起点，不粘贴旧成绩、旧图或逐步任务日志。正式候选按同一解析协议完成完整原件的质量与资源复验；若要应用到 MO-Parse 服务，再单独核对服务转换、真实接口和持久结果，并按授权决定是否更新运行配方。解析调优与服务发布互不代替。
