# MO-Parse 评测任务

## 1. 当前任务：expected-only

<a id="current-task-expected-only"></a>

现有 `pdf_sample/parsing/expected/` 中 canonical expected 是本轮唯一答案。只读其文字和现有选段声明，比较保存的原生文字与结构、实际最终 Markdown 及原执行测量。旧字段索引、标注答案、文档编号、评分和人工裁定不提供答案，也不限制覆盖。不核验或改写参考、原件、映射、标注、资产和数据包，不另建 Gold。

评测、诊断与验收均不调用视觉能力、视觉模型或多模态裁判，不使用 `view_image`、截图、渲染、裁剪、原 PDF 文字层、OCR、候选图片或其他解析器另取答案。人工文字阅读仅诊断软件问题；所有公开成绩来自共同程序。语料制作的原页视觉审核规则属于另行授权任务，不是当前评测前置条件。

本轮不重新运行模型、Full 或额外六份 PDF，不操作 GPU、TTS、在线服务及其他项目，不部署，不增加公开 API。候选的必要 CPU 回放严格沿用原配置输入权限，不挂载 expected；P08 不读取 PDF 文字层、矢量文字或其他管线补答案。已有声明内的 P07 来源处理与评分程序严格隔离，不新增补充方法。

## 2. 对象和保存范围

八组固定配置由[管线计划](pipelines-to-test.md)维护，格式及读取由[逐组说明](../docs/pipelines/README.md)维护。

| 比较 | 输入 | 答案与判分 |
| --- | --- | --- |
| P01–P08 横向比较 | `benchmark/runs/lite/` 的有效 quality800 原生结果 | 同一只读 expected 选段、全部目标、相同分母、等价规则、失败政策及冻结程序 |
| P07/P08 配对比较 | 同组原生、`service/baseline/` 唯一修改前正文、`service/current/` 修改后正文 | 同版程序重新评分；正文只读实际 `final.md`，内部 IR 和未打印关系不能补分 |

唯一基线由原 `after` 原位移动保全，正文、必要资产、执行配置和原计时字节保留。删除 earlier、before、旧成绩、错误报告、图表、失效冻结、临时程序和错误评分软件副本，不归档、不留兼容目录。有效原生答案及原 observation 不改写。只维护 [Lite 报告](reports/lite/report.md)，方法附录、数据和图件放相邻目录，不维护工程迭代日期报告或累计历史收益。

## 3. expected 目标及完整性

读取现有 manifest/source-map 已声明选段，不重建来源映射。程序临时展开每个选段的完整可见文字、明确表格字段及业务要求，并保留 expected 路径、行范围、字面范围和目标之间的追溯。标题、正文、列表、说明、单位、附注、否定及明确引用都不能因旧索引未标注而退出比较。

普通正文含冒号、分号或结尾冒号，不因此成为字段。只有明确的记录语法才额外提取业务事实；段落其余文字继续比较。单格多个明确事实分别读取。每个预期可见范围必须有正文目标或完整业务要求承接；字段提取剩余文字生成正文目标，不能被丢弃。覆盖验证同时检查这些文字范围和要求，并用独立遗漏反例约束。元素编号齐全、目标数量一致和全部二元判定仅是必要条件，不单独证明覆盖或正确性。

目标是评分时的临时计算与追溯结果，不成为可编辑答案。评分器没有参考写入或修复入口。参考真实性和历史审核状态不由评分确认。

## 4. 指标与匹配

### 4.1 普通文字

主结果分别展示内容定位覆盖（定位目标/全部文字目标）、字符定位覆盖（已对齐 expected 字符/全部 expected 字符）、字符保全（对齐中相同字符/全部 expected 字符）、已对齐范围严格 CER，以及 S/D/I、缺失、重复、错字和断裂诊断。字符保全包含缺失目标的零保全；CER 的已对齐分母明确列出，不把定位不到的内容当作良好对齐。

整段完全匹配率只作诊断，不能称为正文准确率。若计算未定位内容暂按删除处理的目标 CER，明确命名为诊断，不能改称全文 OCR 准确率。数字、名称、限定与否定差异保留具体预期范围和候选范围。不能因提取业务字段而停止比较段落其余内容。

字宽政策将 U+FF01–U+FF5E 对应到 ASCII，U+3000 对应空格；允许排版换行和连续空白折叠为一个空格，绝不无条件删除空白，`1 2` 与 `12` 不等价。严格字符诊断始终保留。只有明确排版语法可变化，不修正数字、符号、小数、负号、会计括号、单位或业务含义。

### 4.2 表格和明确业务事实

主结果分别是“值与业务标签正确数/全部业务目标数”和“完整业务信息正确数/全部业务目标数”。完整要求包含 expected 明确表达的主体、指标、值、单位、期间、父分组、附注、限定及否定；缺失或错误均保留分母计错。读取覆盖和已比较部分条件正确率仅作诊断，不能替代全目标成绩。

先按完整业务身份和明确范围定位，再比较值及限定。同值出现在其他表不能救正当前目标；相互矛盾的陈述不能择优。候选不必复制 expected 分块、表格方向、合并格写法、列表层数或私有关系字段。等价表达仍须保留全部业务关系；真实关系缺失不能强行判等价。

带子内容的明确命名记录声明主体，其名称用于定位主体身份，后续指标仍须独立比较。普通命名属性和数值不因此成为身份。嵌套列表的列名及子正文按已声明主体和字段范围比较；候选的共享表头可以关联多条正确记录，不要求为每条记录重复印刷表头，错误主体下的同文不能救正。

百分号与明确独立单位允许同值表达，年度范围连接号可有排版差异，句末正文标点可作表达等价；业务值中已打印逗号两侧的显示空白可变化，逗号本身必须保留，不能把没有分隔符的两个数字连写。严格字面差异另报。不得换算、重新计算、纠正数值或符号。脚注、上标和幂只在当前候选已有格式及明确附注范围支持时读取，不能按期望答案选择解释。

### 4.3 上下文和顺序

检查 expected 明确要求的标题归属、段落连续、父分组、续表、期间和附注范围，不增加参考没有表达的原始版式、标题树或结构标注。候选同一文字拆分为相邻块可连续读取；插入否定或其他文字不能跳过。业务绑定依据当前候选自己的表头、记录、标题和明确范围，不从相邻其他表借关系。

标题定位允许已有文字的相邻块、中文标题换行及枚举间距、引号字形和图表编号在相邻图题前后的变化；不合并数字之间的空格，不补写缺失标题词，严格字符差异仍保留。重复叶标题同时受已打印父范围约束，正文中的附件引用不提前启动后续表格。较完整的长文字范围先取得自己的字面位置，避免短名称前缀占走完整名称；正确的独立文字不重复认领同一范围，近似段落中的插入文字仍可作为独立说明比较。

### 4.4 图片和失败

expected 明确图题及正文引用作为文字评价。图片 alt 仅作字面诊断，不计为图片理解能力。候选资产和引用交付独立记录，数量、哈希及文件存在不证明图片内容正确。不开展图像语义任务。

每个目标最终仅为 correct 或 incorrect。真实缺失、错误、解析失败保留全部分母并计错；评分软件尚不会读取候选已有表达时必须先修软件，阻止公开成绩，不能批量改称管线错误或另名“未判定”。不删目标，不按管线、公司、文件名或预期答案写例外。

## 5. 共同读取与验证

候选读取器不接收 expected 答案。P01/P02 读取 Docling 阅读树、文字项、单元格、跨度、角色及引用；P03/P04 读取 Paddle `parsing_res_list`、区域正文、HTML/Markdown、顺序及媒体；P05 仅以 GLM `json_result` 为主答案，其他阶段作为审计视图；P06/P07 读取 DocVortex typed blocks、行内 spans、HTML 表体、caption、footnote 及明确续接；P08 读取视觉 SDK `ContentBlock[]` 的 content、type、顺序及明确续接。混合管线 GLM 分支独立忠实读取后按已有页序组合，不择优拼答案。

先固定独立构造的正反例，再修实现，至少覆盖：正文标点；单格多事实；真实 SDK/HTML/GFM/列表/分块的完整读取链；多层表头、跨度、多年度、共享单位、局部期间、重复标签、父分组与附注；年度交换、跨表借值、单位错配、负号、否定、附注误绑和冲突；格式等价及关系真丢失；P01–P08 标签与样本名称不影响成绩；内部元数据不改变 final.md 分数；无视觉/PDF评测输入及无参考写入。真实缺陷转成通用反例，不为具体答案设特例。

小批真实保存结果跑完整链以验证读取，再冻结评分代码和依赖。已知反例未修复，不进入全量重评或发布结论。共同评分变化须统一重评所有受影响原生和正文，不能继承旧分数。复现一致仅证明复现，不能代替判分正确性验证。

## 6. 原始执行与资源口径

保存的每组 quality800 一轮与固定 perf80 三轮分开展示；重复不增加独立文档样本。原始解析从 worker 处理开始到原生结果、忠实 Markdown 和必要资产就绪，包含必要 PDF 渲染、解析及导出，排除 HTTP、排队、下载、纯持久化及 MO-Parse 服务转换。初始化与预热单列。不重新推理或回填原处理时长。

原生历史耗时和确定性 CPU 后处理回放耗时分列，不相加冒充新端到端测量。后处理改变时每组完成800页回放、80页三轮及独立预热；仅评分改变时只重评保存输出。

内存、显存来自原观测，列采样窗口、覆盖与缺失。独立峰值不相加，预算不冒充实测；TTS、整卡和归属未知显存不归给受测管线。全协议峰值包含初始化、预热与所有轮次，不改称 quality800 单独峰值。披露 TTS 共驻、负载不受控及观察不确定性，不称独占或空闲 GPU。共同展示质量、时间、内存与显存，不用加权分数或二维投影宣布整体冠军。

图表使用 DejaVu Sans、Noto Sans CJK 和显式 sans-serif 回退，数学字体为 dejavusans，禁用 TeX；PDF 嵌入字体，SVG 字体栈和 PDF 字体名通过程序检查，不进行原页或候选图片视觉验收。

## 7. P07/P08与MO-Parse最终输出的配对评测

先保全唯一 baseline，修共同评分并同版重评八组原生及 baseline，再按错误追溯区分原生缺失、评分读取错误、适配丢失、关系绑定错误与正文渲染损失。只修原生已有信息能够支持的真实交付问题，不能从 expected 或别的管线补写。

采用同时要求：baseline 正确内容没有新增损失；原生正确内容在当前实际 Markdown 仍正确；布局正文没有伪造业务关系；收益来自实际交付文字。报告逐项新增正确、原正确损失、新增错误和剩余缺陷。评分器补读与正文改善分开，删除旧历史迭代框架，不为了必改正文而制造变更；发现真实转换损失也不能只修评分就结束。

## 8. 报告与完成

报告主文回答两项研究问题，附录及数据保留 expected 实际比较范围、提取依据、全部逐项判定与候选证据、最早失败阶段、文档/家族/既有类别配对差异、真实正文变化、损失、剩余问题和开发暴露。Lite 参与开发的材料不能宣称独立未见测试集。

入口拒绝版本混用、目标缺失、已知读取缺陷、评分未完成或汇总与逐项不符。完成要求定义一致、独立反例及真实格式读取验证、完整共同程序对照、同版统一重评、真实转换问题处理及退化验证、可追溯报告和同步文档。测试、提交、文件数、耗时和报告生成都不单独构成完成。

通用检查仅用于代码和非语料文档，永久排除 `pdf_sample/`、`pdf_sample_extra/`、`pdf_page_images/`、`datasets/`、`benchmark/reference-decisions/`、`benchmark/runs/` 和 `benchmark/reports/`，包括显式路径调用。真实候选专项评分独立执行。工具用法见[评测模块](../moparse_eval/README.md)，后续步骤见[技术路线](../docs/engineering/technical-route.md)。
